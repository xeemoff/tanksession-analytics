# План развития TankSession Analytics

## Сейчас: 1.0.0-rc1 — полный кандидат для испытаний

Программные этапы 0.5–0.7 объединены в кандидате 1.0.0-rc1. Это изменение плана нумерации, а не утверждение о прохождении игровых испытаний. Целевой клиент — **1.46.0.0**, статус живого протокола новой версии — **pending**.

### Реализовано в коде

- [x] Локальный JSONL-журнал, принадлежность подтверждённому аккаунту, дополнение неполных записей и дедупликация.
- [x] Ограниченная очередь готовых результатов, повторы и таймауты восстановления; очистка старого контекста при смене аккаунта.
- [x] React/TypeScript, Gameface, фильтры, графики, Session Coach, рекорды, полнота выборки и цели.
- [x] История всего загруженного журнала по пять строк на страницу и подробности результата.
- [x] Необязательные поля карты, уничтоженной техники, выживания, стрельбы, базового опыта и начисленных кредитов; показатели считают только известные значения.
- [x] Разделение сессий по паузе от 60 минут между получениями результатов; сравнение при достаточной сопоставимой выборке.
- [x] Личные профили аккаунтов, сохранение фильтров и вида, редактор целей, CSV без ID аккаунта и боя.
- [x] Атомарная запись профиля с предыдущей копией; сохранение старых целей и игровой истории.
- [x] Браузерный просмотр собственной истории только для чтения по умолчанию; явный `--allow-write` для записи и временный профиль демо.
- [x] Windows-установщик с SHA-256, проверкой назначения пакета, резервированием прежней версии и откатом.
- [x] Упаковка Windows ZIP, выпуск по тегу и автоматический gate для стабильной версии.
- [x] Автоматические сценарии Python, TypeScript, браузера, CPython 2.7 и установщика Windows. Фактический результат зависит от CI конкретного коммита.

Чистые кредиты поддержаны в формате записи, но игровой адаптер не вычисляет их из неполных расходов. Карта может показываться ключом `arena:<ID типа карты>`. Новые игровые поля остаются неподтверждёнными до сверки с клиентом.

### Ранее подтверждено в игре на rc4–rc8

- [x] Обычный завершённый собственный бой записан; первая запись сверена с официальным результатом.
- [x] Gameface открывается через F8, закрывается крестиком, работают часть фильтров и вкладок; центрирование подтверждено в rc8.
- [x] Ранее записанная история сохранена при обновлениях и перезапусках.
- [x] Обработчик результатов ангара подключается, кэш отвечает; старые ожидания не восстановлены.

Эти результаты относятся к прежним пакетам. [Протокол](CLIENT_VALIDATION_RU.md) сохраняет версии, даты и границы проверки.

## До стабильной 1.0.0

- [ ] Проверить точную новую сборку на клиенте 1.46.0.0 и записать её SHA-256.
- [ ] Сверить победу, поражение, нулевой урон и поддерживаемые дополнительные поля с официальными итогами; не считать неизвестное значение нулём.
- [ ] Подтвердить свежий отложенный результат и отсутствие дублей. Отдельно зафиксировать случаи, когда клиент не предоставляет результат.
- [ ] Проверить смену аккаунта, реплей, выход в бой, отключение и перезапуск.
- [ ] Проверить полную историю, детали, графики, сессии, сохранение настроек, цели и CSV в реальном Gameface.
- [ ] Проверить установку, обновление, откат и удаление с сохранением истории.
- [ ] Измерить открытие окна и поведение на фактическом объёме истории.
- [ ] Завершить [машинный протокол](release-validation.json) и подробный отчёт; сравнить хеш испытанного пакета с публикуемым.
- [ ] Выпустить стабильный тег и файлы, дать прямую загрузку и инструкцию; при публикации на форуме учесть актуальные правила и модерацию.

## После 1.0.0

Поддержка обновлений клиента, исправления по воспроизводимым сообщениям и уточнение дополнительных метрик. Локализованные названия карт и точная экономика добавляются только при подтверждённом источнике данных. Новые аналитические выводы должны объяснять свою выборку и не приписывать причины, которых нет в журнале.
