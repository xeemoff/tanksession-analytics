# Готовность TankSession Analytics 2.0

## Назначение этапа

27 ноября 2026 владелец проекта одобрил развитие до 2.0, затем отдельный этап полировки и изучения устройства проекта для собеседований. Работа ведётся от опубликованного [1.0.0-rc2](https://github.com/xeemoff/tanksession-analytics/releases/tag/v1.0.0-rc2), коммит `5174fc289733b23f225096dd77e5ddc913be28b3`.

Номер текущего кандидата — **2.0.0-rc3**. Он исправляет оставшиеся ошибки прокрутки и отчётов после частичной приёмки RC2 и добавляет обновление мода и менеджера по кнопке. Стабильный **2.0.0** требует полной игровой приёмки конкретного пакета. Версии 1.1–1.4 используются как группы согласованного объёма; отдельные промежуточные релизы не имитируются.

## Объём и критерии

| Группа | Проверяемый результат | Граница |
|---|---|---|
| 1.1: расширенная аналитика | Карты, класс/уровень/нация, календарь, часы/дни, экономика техники | Только известные поля; время получения в UTC; старый журнал не перезаписывается |
| 1.2: Coach и отчёты | Наблюдения с размером выборки, разброс, предложение цели, периоды | Никаких причинных выводов из сводных результатов; явное принятие цели |
| 1.3: интерфейс | Темы, блоки панели, поиск/сортировка, интерактивные графики, карточки | Оригинальные иллюстрации классов; неизвестные значения остаются неизвестными |
| 1.4: удобство | Графический менеджер, поиск игры, удаление/возврат, обновления, снимки истории | Полный снимок вместо слияния журналов; сеть только по кнопкам проверки и установки выпуска |
| 2.0: C++ | Используемый офлайн CLI, библиотека, адаптер, тесты, замеры | Отдельный процесс вне игры; явные лимиты чисел и протокола |
| Подготовка к разбору | Архитектура, карта кода, решения, ограничения и упражнения | Учебный этап начнётся после реализации и полировки |

Для чистой экономики дополнительно подтверждена справочная цепочка режима 22 (RANKED); он включён вместе с 1/24 при прежних проверках компонентов, принадлежности и единственной машины. Другие режимы допускаются только после подтверждения полной формулы. Группировка наблюдаемых начислений по режимам и технике не превращает неизвестный чистый итог в ноль. Наличие этого ограничения нельзя описывать как поддержку чистых кредитов всех режимов.

## Исправления RC2

RC2 исправляет подтверждённые расхождения RC1: сохранение профиля без обязательного `ctypes`, отображение ошибки операции вместе с историей, прокрутку и стили Gameface, вёрстку истории, локализованную подпись по точному типу и дополнительный опыт конкретного боя. Сохранение использует атомарный API, когда он доступен; fallback — восстанавливаемая последовательность для одного писателя. Резервные снимки включают файлы восстановления профиля.

Дополнительный XP не вычисляется из дневных агрегатов. Новое отдельное событие требует наблюдённого предложения и подтверждённого применения; обычные конфликты известных полей остаются строгими. Компактирование должно сохранить происхождение этой поправки. Бонус, применённый до наблюдения предложения модом, этим механизмом не восстанавливается.

Добавлены проверки отсутствующего `ctypes`, отказов записи/возврата, настоящего завершения дочернего процесса между переименованиями, повторного открытия, безопасной ошибки Gameface, снимков менеджера, прокрутки/вёрстки и повторных событий XP. Таблица выше относится к RC1; окончательные результаты кода RC2 приведены ниже.

Первый [прогон RC2 46036673914](https://github.com/xeemoff/tanksession-analytics/actions/runs/46036673914), коммит `ac1aef4cb37bc147caa07c8184dfdc8bd3c4cde0`, прошёл CPython 2.7, UI (60 Node / 24 browser), Linux и C++; Windows Python выявил два отказа офлайн-инструментов. В компактировании сравнивались разные Windows-значения `ctime` у `stat(path)` и `fstat(fd)`: теперь у каждого API собственная исходная сигнатура, проверки изменений и резервирование сохранены. Preview закрывал ранний отказ POST до получения тела: теперь допустимое ограниченное тело дочитывается с общим сроком 10 секунд до отказа, все проверки команды выполняются до мутаций. Добавлены воспроизводящие регрессии; skips и повторные попытки вместо исправлений не вводились.

Повторный [полный CI 46038083441](https://github.com/xeemoff/tanksession-analytics/actions/runs/46038083441) на `88658110693f8864b11715f2225655b85df3baa4` прошёл все восемь заданий. Windows: 497 тестов, 6 платформенных skips; UI: 60 Node и 24 browser. В [галерее](SCREENSHOTS_RU.md) сохранены девять PNG этого запуска, включая три кадра с имитацией игрового транспорта; переходы отключены только при захвате.

Дополнительная проверка обнаружила, что автоматическое восстановление `.rollback` могло переименовывать файл даже в браузерном режиме «только чтение». Workspace получил явный read-only режим: валидная копия читается без rename/cleanup, команды записи и экспорт запрещены; игра сохраняет штатное восстановление. Регрессии сравнивают имена и байты всего каталога до/после реальных HTTP initialize/GET, затем отдельно подтверждают восстановление с `--allow-write`.

## Исправления и проверки RC3

- Совместимость прокрутки: доступная высота определяется без обязательного `clientHeight`; некорректные размеры не превращаются в `NaN`, событие колеса отменяется после перемещения или на известной границе. Кнопки имеют текстовые подписи, период отчёта сохраняет горизонтальное расположение. Дефект RC2 воспроизведён отрицательным контролем без `clientHeight`.
- Обновление через менеджер: отдельная кнопка скачивает выбранный выпуск, проверяет архив до загрузки его кода, сохраняет прежнюю установку и переключает менеджер на отдельную папку версии. Каналы stable/RC, явное действие пользователя и ручной способ установки сохранены. Первый переход с RC2 на RC3 требует ручного архива.
- Записаны результаты RC2, включая 3510 + 2340 = 5850 XP и сохранение после перезапуска по подтверждению оператора; не перенесены в статус проверки нового RC3.

Параллельный [PR CI 46047881160](https://github.com/xeemoff/tanksession-analytics/actions/runs/46047881160) того же коммита завершил семь заданий успешно; Python 3.9 обнаружил нестабильность прежнего теста обезличенной диагностики. Проверка запрещала подстроку `99` во всех сообщениях, включая предусмотренную строку локального пути журнала. Случайное имя временного каталога могло содержать эти цифры. Отрицательный контроль с заданным путём подтвердил: единственное совпадение находилось в точной строке стартового пути, а сообщение конфликта аккаунтов оставалось обезличенным.

Тест исправлен без изменения игрового кода: путь всегда содержит оба синтетических ID `99` и `88`; разрешена ровно одна полностью совпадающая строка стартового пути, все остальные сообщения и ошибки проверяются на отсутствие обоих ID. Точный текст сообщения конфликта также проверяется. Локально прошли все 42 теста адаптера; искусственные утечки обоих ID при инициализации обнаруживаются. **Полный CI коммита с этой правкой теста ещё должен пройти перед слиянием**; успешный прогон `816b798` не заменяет эту проверку. Публикация повторяет обязательные проверки на коммите слияния.

Статус нового игрового пакета RC3 — **не испытан в клиенте**. Физическое колесо и кнопки Gameface, а также обновление мода и менеджера на компьютере оператора остаются отдельными проверками [#9](https://github.com/xeemoff/tanksession-analytics/issues/9) и [#10](https://github.com/xeemoff/tanksession-analytics/issues/10). Существующие результаты RC2 ниже относятся только к RC2.

## Игровая приёмка

27 ноября 2026 выполнены частичные испытания RC1 и RC2 на клиенте 1.46.0.0. В RC2 подтверждены сохранение контраста, подпись Т-34-85, пять строк и отдельная пагинация, обновление XP одного нового боя после бонуса. На просьбу проверить 12 записей, 5850 XP и контраст после полного перезапуска оператор подтвердил сохранность. Колесо и обе кнопки прокрутки не работали, кнопки периода отчёта располагались вертикально. Происхождение пакетов, различие опубликованного и проверенного установленного хешей и границы каждой сверки записаны в [протоколе](CLIENT_VALIDATION_RU.md).

[release-validation.json](release-validation.json) имеет `release_version: 2.0.0`, `status: pending`, незаполненные хеш/дату и все 13 проверок `false`. Результаты rc4–rc8, 1.0 RC2 и частичной приёмки 2.0 RC1/RC2 не переносятся на новые байты.

Дополнительно в рамках метрик/интерфейса нужно сверить карту и класс/уровень/нацию, выборку отчётов, сортировку по всей истории, смену тем/блоков, принятие цели и работу окна при выходе из ангара. В рамках установки — запуск менеджера на пользовательском компьютере, обновление, возврат пакета, экспорт/импорт тестовой копии данных.

Полный перечень: [CHECK_CLIENT_RU.md](CHECK_CLIENT_RU.md). Фактическое свидетельство: [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md). После смены метаданных на stable меняется `.mtmod`; его новый SHA-256 должен быть проверен отдельно.
