# Окно TankSession в ангаре — 2.0.0-rc3

**Исправления RC2 ещё не испытаны в клиенте.** В 2.0 RC1 подтверждены открытие новых разделов и добавление боя, но выявлены ошибки сохранения вида, прокрутки и вёрстки. Исторические результаты и обнаруженные ограничения находятся в [протоколе](CLIENT_VALIDATION_RU.md). Chromium-демонстрация и имитация нативных API не подтверждают работу новой сборки в игре.

## Разделы окна

| Раздел | Содержимое |
|---|---|
| Прогресс | Число записанных боёв, процент побед среди известных исходов, средний урон, Session Coach и локальные рекорды |
| Динамика и цели | До 24 отдельных результатов, подробность выбранного столбца, до 60 точек скользящего среднего, прогресс целей |
| История боёв | Вся выбранная история по пять записей на страницу, дополнительные известные поля отдельного боя |
| Сводка | Исходы, серии, помощь, дни, техника, дополнительные метрики, ID карт и сессии по времени получения |
| Аналитика | Карты, классы/уровни/нации, карточки техники, календарь UTC и экономика |
| Отчёты | Неделя, месяц и вся история, покрытие показателей и предыдущий период |
| Настройки | Темы и блоки панели, плотность и контраст, стартовая вкладка, сохранение выбранных фильтров, создание/изменение/удаление целей, CSV |

Фильтр техники применяется к истории и аналитике. Окно 10/30/100 определяет сравнение и скользящее среднее; оно не ограничивает всю историю или CSV. Для нового запроса страницы доступны все результаты. Старые источники без `pagination` сохраняют прежнюю ограниченную историю без обещания доступа ко всему журналу.

Данные относятся только к подтверждённому текущему аккаунту. Неизвестные значения показаны как отсутствующие, а не как ноль. `complete` означает полноту исхода, урона и полученного опыта, а не всех дополнительных полей. Карта показывается локализованной подписью при наличии точного каталога; иначе сохраняется ID типа арены. Смысл новых полей, целей и сессий описан в [DATA_AND_UI_RU.md](DATA_AND_UI_RU.md).

[Галерея](SCREENSHOTS_RU.md) содержит изображения с явной версией и происхождением. Браузерные снимки, включая имитацию игрового транспорта, не подтверждают работу встроенного Gameface.

Начиная с 1.0 RC2 подпись машины отделена от её ключа. Фильтр, цель и экспорт следуют подтверждённому типу или точному внутреннему имени. Старая неоднозначная подпись остаётся отдельной группой истории. Базовый и бонусный опыт показаны отдельно; чистые кредиты появляются только при полном наборе компонентов поддержанного результата. Условия описаны в [контракте](DATA_AND_UI_RU.md).

## Просмотр без установки в игру

Для готового архива `TankSession_Analytics_2.0.0-rc3_Preview.zip` распакуй весь архив и запусти `demo_hangar.cmd`. Нужны Python 3.9+ и браузер. Наличие конкретного архива проверяй у успешной сборки соответствующего коммита.

Из исходников:

```powershell
cd ui
npm ci
npm run build
cd ..
python tools/preview_ui.py --demo
```

Нужны Node.js 20+ для сборки и Python 3.9+ для сервера. Сервер слушает `127.0.0.1:8770`; `--port 0` выбирает свободный порт. Остановка — `Ctrl+C`. Демо использует вымышленные бои. Изменения демо-профиля и пробный CSV относятся к временному хранилищу; `sample_data` остаётся исходным.

Для своей истории:

```powershell
python tools/preview_ui.py --data "D:\your-folder\battles.jsonl" --account "ID_СВОЕГО_АККАУНТА"
```

По умолчанию этот режим доступен **только для чтения**. Необязательный `--goals "D:\your-folder\goals.json"` подключает прежний файл целей. Сервер закрепляется за одним аккаунтом; HTTP-параметры его не меняют.

Если нужны сохранение настроек, целей и CSV из браузера, добавь `--allow-write`. Профили и экспорт появятся рядом с указанным журналом, сам JSONL не переписывается. Для испытания новых записывающих команд удобнее отдельная копия каталога данных при закрытой игре.

## Внешний загрузчик

Нативное окно использует **OpenWG Gameface**. Адаптер изучен по документации **v1.2.2**: `openwg_gameface.on_ready()` и `res_id_by_key()`. Загрузчик устанавливается отдельно, его файлы и игровые ресурсы в TankSession не включены.

- [Документация OpenWG Gameface v1.2.2](https://gitlab.com/openwg/wot.gameface/-/blob/v1.2.2/README.md)
- [Релизы загрузчика](https://gitlab.com/openwg/wot.gameface/-/releases)
- [Файл OpenWG Gameface 1.2.2 для «Мира танков»](https://gitlab.com/api/v4/projects/68695173/uploads/43577d5bab856523c1b7a6dcada27f23/net.openwg.gameface_1.2.2.mtmod)

Для указанного файла 21.11.2026 проверены размер **48 445 байт** и SHA-256 `2BB65F28663E3AB34B5A1102A1BBD1F6E17A65E1F6A898A8645C4AB732B50184`. Это историческая проверка содержимого скачивания. Открытие окна с ним на rc5 описано отдельно в протоколе; совместимость 2.0.0-rc3 этим не подтверждается.

Нужен вариант загрузчика для «Мира танков» с расширением `.mtmod`. По документации он объединяет регистрации в `res_mods/<версия>/gui/unbound/gen/res_map.json` и при изменении ресурсов может однократно перезапустить клиент. TankSession сам перезапуск не вызывает. Декларация ресурса включена в пакет независимо от настройки открытия окна.

## Включение окна

1. Закрой игру. Подготовь кандидат TankSession из успешной сборки и отдельно совместимый OpenWG Gameface.
2. Помести пакеты в `mods/<точная_версия_клиента>/`. Оставь одну версию TankSession. Сохрани весь каталог `mods/configs/tanksession_analytics/`, включая журнал, pending, профили и цели.
3. Дополни `settings.json` рядом с журналом, сохранив остальные существующие настройки:

```json
{
  "experimental_gameface_ui": true,
  "experimental_cache_recovery": false
}
```

4. Запусти игру и дождись ангара. Проверь строку запуска TankSession и `Gameface: experimental hangar window available on F8` в локальном логе.
5. Нажми **F8**. Повторное F8, **Esc** и крестик должны закрывать окно. Если совместимый `gui.modsListApi` уже доступен, адаптер также пытается добавить пункт меню; он не обязателен для F8.

Переключатели читаются при запуске. Оба экспериментальных пути выключены по умолчанию. Окно требует подтверждённый аккаунт в ангаре и доступную проверку реплея. Отсутствующий загрузчик отключает дополнительный экран, сохраняя независимый основной сбор результатов.

Поддерживается UTF-8 с BOM и без него. Предел `settings.json` — 4 КиБ, файла целей и профиля — 64 КиБ.

## Сохранение вида, целей и CSV

Во вкладке «Настройки» выбери плотность, контраст и стартовый раздел, затем нажми **«Сохранить вид и фильтры»**. Сохраняются также выбранные сверху техника и окно 10/30/100. Настройки относятся к текущему аккаунту и восстанавливаются при открытии.

Цель задаётся для одной машины: средний урон 1–50 000, окно 10–1 000 боёв. Сохранение заменяет цель той же машины с тем же размером окна. Достижение проверяется только при полном количестве боёв и известном уроне каждого из них. Удаление цели не удаляет бои.

Профиль находится в `profiles/` рядом с журналом. До собственного изменения целей он может наследовать прежний `goals.json` только для чтения. После изменения используется список профиля; пустой список означает отсутствие целей. Повреждённый legacy-файл не блокирует уже сохранённый собственный список. Если необходимый профиль или legacy-файл не прочитан, окно сообщает ошибку и блокирует запись поверх него.

**«Сохранить CSV»** экспортирует всю выбранную историю, независимо от страницы и окна сравнения. Файл создаётся в `mods/configs/tanksession_analytics/exports/`; интерфейс показывает имя и число строк. CSV использует UTF-8 с BOM и разделитель `;`, содержит подпись и необязательный ID типа техники, базовый/бонусный опыт и известные кредиты. ID аккаунта и боя исключены. Отсутствующие значения остаются пустыми. В демо экспорт создаётся во временном каталоге сервера.

## Как устроен обмен

Запрос нового интерфейса:

```json
{"protocol":1,"request_id":"ui:1","vehicle":"name:ussr:R04_T-34","window":10,"page":0}
```

Команды `initialize`, `save_preferences`, `save_goal`, `delete_goal`, `export_csv` описаны в [контракте](DATA_AND_UI_RU.md). Python проверяет поля, типы и допустимые значения. UI не передаёт аккаунт, имя выходного файла или путь.

`vehicle` содержит selector из `vehicles[].name`, а подпись берётся из необязательного `label`. Поле `vehicle_label` сопровождает selector в истории, целях и аналитике. Старые запросы с подписями разрешаются по точному однозначному соответствию своего аккаунта; старые снимки без дополнительных подписей и `xp_bonus` остаются допустимыми.

Запрос ограничен 16 КиБ, снимок — 512 КиБ. Обычные запросы просмотра объединяются на 150 мс; записи и экспорт выполняются по очереди. Автообновление не повторяет последнюю мутацию. Frontend принимает только актуальный `request_id`.

Контекст окна проверяется раз в 0,5 с без пересчёта истории. Закрытие, переход в бой и смена аккаунта отменяют отложенные обращения и уничтожают окно. Проверки нативного жизненного цикла новой версии всё ещё нужны в игре.

Браузер использует тот же контракт. Для команд требуется `POST /api/command`, `Content-Type: application/json` и `X-TankSession-Request: 1`. Источник выбирается явно: `?demo=1` либо `?local=1`. Без параметров приложение ожидает Gameface; скрытой подмены реальных данных демо нет.

## Сборка и проверка

```powershell
python tools/generate_ui_fixtures.py --check
cd ui
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
cd ..
python tools/package_preview.py

```

В `.mtmod` входят собственные Python-модули, HTML, JS, CSS, лицензии UI, регистрация Layout и `meta.xml`; состав проверяется явным manifest. Интерфейс собран без CDN, внешних шрифтов и игровых изображений. [Документация загрузчика](https://gitlab.com/openwg/wot.gameface/-/blob/v1.2.2/resources/in/gui/gameface/js/index.js) описывает предоставление `engine`, модели и окружения представления; реальные возможности движка требуют нативной проверки.

Для 2.0.0-rc3 сначала проверь обе кнопки «Вверх»/«Вниз», направление и шаг колеса, достижимость нижних блоков и горизонтальный выбор периода отчёта. Затем повтори сохранение контраста и полный перезапуск: RC2 прошёл этот отдельный сценарий, но его успех не заменяет проверку нового пакета. Все разделы, цели/CSV, переходы контекста, производительность и свежие поздние результаты остаются в полном плане [CHECK_CLIENT_RU.md](CHECK_CLIENT_RU.md). Результаты — [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md).

## Отключение и удаление

При закрытой игре установи `"experimental_gameface_ui": false` и перезапусти клиент. Для удаления самого мода удали только его `.mtmod`. Каталог истории и профилей можно сохранить. Внешний загрузчик может требоваться другим модам; его удаление рассматривается отдельно.


## Совместимость прокрутки в RC3

В RC2 обработчики колеса, кнопок и клавиш вычитали `clientHeight` без проверки его наличия. В Gameface поддержка этого свойства добавлена только в [1.54.0](https://docs.coherent-labs.com/cpp-gameface/releases/release_1540/); версия Cohtml установленного клиента не установлена. Воспроизводимая проверка без `clientHeight` даёт `NaN` в RC2, а wheel уже отменён обработчиком. Это объясняет совместимый с наблюдением сценарий отказа, но не измерение версии движка пользователя.

RC3 определяет доступную высоту через проверяемые DOM-свойства, не записывает некорректное смещение и отменяет wheel после фактического перемещения или на известной границе. При невозможности обработать событие штатная прокрутка остаётся доступной. `scrollTo()` не требуется. Кнопки имеют текстовые подписи вместо отсутствовавших в игровом шрифте стрелок; клавиши Page Up / Page Down / Home / End используют общий механизм. Браузерное колесо сохраняет штатное поведение. Физические направление и шаг требуют проверки в игре.
