# Окно TankSession в ангаре — экспериментальная интеграция Gameface

**Версия 0.4.0-rc6. В rc5 подтверждены открытие окна и фильтры в установленном клиенте; обнаружены дефекты прокрутки и вёрстки. Исправления rc6 ещё не испытаны в игре.** В проекте реализованы интерфейс React/TypeScript, Python-модель данных и адаптер окна. Автотесты проверяют собственную логику, имитацию нативных API и браузерный просмотр. Они не заменяют проверку загрузки и отображения в конкретной версии игры.

## Что показывает окно

В rc6 три вкладки, история по пять строк на страницу, выбор техники по страницам и пояснение вместо расширения карточки. Выбор техники, окна 10/30/100 боёв, число боёв, процент побед и средний урон, график скользящего среднего, сравнение двух непересекающихся периодов, цели и 12 последних результатов. На графике отображается до 60 точек; неизвестные значения создают разрывы. Время строки истории означает первое получение результата модом.

В rc5 добавлен [разбор прогресса](SESSION_COACH_RU.md): средний урон и медиана двух полных периодов на одной машине, полнота выборки и локальные рекорды. При одном бое раздел показывает исходную точку и число результатов, которых ещё не хватает.

Данные относятся к текущему подтверждённому аккаунту. Аккаунт нельзя выбрать командой из интерфейса. Если источник недоступен, прежние показатели очищаются. Демо всегда имеет отдельную отметку. Фильтры по датам, выбор аккаунта и CSV остаются в прежней браузерной панели.

## Быстрый просмотр без установки в игру

Самый короткий путь — готовый `TankSession_Analytics_0.4.0-rc6_Preview.zip` из artifact `tanksession-hangar-preview-...` в успешном запуске GitHub Actions. Распакуй весь архив и запусти `demo_hangar.cmd`. Нужны Python 3.9+ и браузер; Node.js для готового архива не нужен.

Для исходного кода нужны Node.js 20+ и закреплённые зависимости:

```powershell
cd ui
npm ci
npm run build
cd ..
python tools/preview_ui.py --demo
```

Сервер слушает `127.0.0.1:8770`, при `--port 0` выбирает свободный порт. Остановка — `Ctrl+C`. Браузерный просмотр не запускает движок Gameface.

Для своей истории:

```powershell
python tools/preview_ui.py --data "D:\your-folder\battles.jsonl" --account "ID_АККАУНТА" --goals "D:\your-folder\goals.json"
```

`--account` обязателен для собственной истории, `--goals` необязателен. Сервер закрепляется за одним аккаунтом. Параметры HTTP не могут сменить его. История читается без записи; отсутствие или недоступность журнала возвращает ошибку.

## Зависимость игрового окна

Адаптер использует публичный интерфейс **OpenWG Gameface**, изученный по документации **v1.2.2**: `openwg_gameface.on_ready()` и `res_id_by_key()`. Загрузчик устанавливается отдельно; его бинарные файлы и ресурсы клиента не включены в TankSession.

- [Документация OpenWG Gameface v1.2.2](https://gitlab.com/openwg/wot.gameface/-/blob/v1.2.2/README.md)
- [Релизы загрузчика](https://gitlab.com/openwg/wot.gameface/-/releases)
- [Скачать OpenWG Gameface 1.2.2 для «Мира танков»](https://gitlab.com/api/v4/projects/68695173/uploads/43577d5bab856523c1b7a6dcada27f23/net.openwg.gameface_1.2.2.mtmod) — публичный файл официального проекта GitLab, проверен 21.11.2026.

Проверенный файл `net.openwg.gameface_1.2.2.mtmod`: 48 445 байт, SHA-256 `2BB65F28663E3AB34B5A1102A1BBD1F6E17A65E1F6A898A8645C4AB732B50184`. Это подтверждение содержимого скачивания; открытие окна с загрузчиком по отчёту оператора отдельно описано в протоколе rc5. Если GitLab временно недоступен, открой страницу релиза автора.

Нужен пакет загрузчика **для «Мира танков» с расширением `.mtmod`**. Вариант для Wargaming World of Tanks использует другой путь регистрации ресурсов и не подтверждает совместимость с Lesta. Не устанавливай оба варианта одновременно. Версию реально использованного загрузчика запиши в протокол испытания.

По документации загрузчик для «Мира танков» объединяет регистрации в `res_mods/<версия>/gui/unbound/gen/res_map.json` и при изменении списка ресурсов может **однократно перезапустить клиент**. Это поведение внешнего загрузчика. TankSession сам не вызывает перезапуск. Регистрация ресурса присутствует в пакете независимо от настройки открытия окна.

## Включение экспериментального окна

1. Закрой игру. Подготовь пакет TankSession из успешной CI-сборки и отдельно совместимый `.mtmod` OpenWG Gameface по инструкции его автора.
2. Скопируй пакеты в `mods/<точная_версия_клиента>/`. Не оставляй рядом несколько версий TankSession.
3. В каталоге `mods/configs/tanksession_analytics/` создай или дополни `settings.json`. Пример структуры находится в [sample_data/settings.example.json](../sample_data/settings.example.json). Существующие настройки сохраняй.

```json
{
  "experimental_gameface_ui": true,
  "experimental_cache_recovery": false
}
```

4. Запусти клиент и дождись ангара. В `python.log` должны появиться строка запуска TankSession и сообщение `Gameface: experimental hangar window available on F8`. Отсутствие ошибки запуска ещё не подтверждает получение боевых результатов.
5. Нажми **F8**. Повторное F8, **Esc** и кнопка закрытия должны закрыть окно. Если совместимый `gui.modsListApi` уже загружен другим модом, адаптер также пытается добавить пункт TankSession; установка меню не требуется для F8.

Настройка читается при запуске мода. По умолчанию `experimental_gameface_ui` выключена. Адаптер требует событие создания ангара, подтверждённый текущий аккаунт и доступную проверку режима реплея. При недоступности этих условий окно не открывается. Отсутствующий загрузчик отключает дополнительный интерфейс; сбор результатов продолжает работать независимо от него.

При обновлении сохраняй `battles.jsonl` и `battles.jsonl.pending.jsonl`: это уже накопленная история и ожидание результатов. Меняется пакет мода, а в настройках — только нужный переключатель. Rc5 принимает UTF-8 как с BOM, так и без него, в том числе файлы, сохранённые Windows PowerShell 5.1.

Цели игрового окна читаются из `goals.json` рядом с журналом. Формат описан в README. Отсутствующий файл означает отсутствие целей, а некорректный файл отображается как ошибка подготовки данных. Предельный размер файла целей — 64 КиБ; настроек — 4 КиБ.

## Что проверить в реальном клиенте

- Открытие и закрытие из ангара, повторное открытие без второго окна, работа фильтров.
- Читаемость кириллицы, размер окна, мышь, клавиатура и отсутствие перекрывающего невидимого окна после закрытия.
- Совпадение метрик с собственной историей и официальным послебоевым экраном.
- Обновление после сохранённого или дополненного результата.
- Закрытие при переходе в бой, выходе из аккаунта и отключении; отсутствие данных прежнего аккаунта после нового входа.
- Запуск с выключенной настройкой и без загрузчика, понятное сообщение при недоступном API.
- Влияние на время открытия ангара и интерфейса на фактическом объёме истории.

Результаты заноси в [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md). Пока они не получены, статус остаётся «не проверено».

## Как устроен обмен

`presentation.build_snapshot()` формирует JSON из журнала и подтверждённого аккаунта. В нативной модели одна строка `payload` и две команды: `onRequest` и `onClose`. Запрос содержит только версию протокола, ID запроса, технику и размер окна:

```json
{"protocol":1,"request_id":"ui:1","vehicle":"IS-7","window":10}
```

Python проверяет поля, размер и допустимые значения. Запрос ограничен 16 КиБ, снимок — 512 КиБ. Аккаунт и arena ID не передаются в снимке. Слишком большие для точного представления в JavaScript метрики отклоняются с диагностикой. Известный ноль сохраняется, неизвестное значение остаётся `null`.

Запросы объединяются с задержкой 150 мс: обрабатывается последний выбранный фильтр. Устаревшие ответы не заменяют новый экран. Контекст открытого окна проверяется раз в 0,5 с без пересчёта статистики. Пересчёт происходит при открытии, изменении фильтра, обновлении истории или явном обновлении. При закрытии очищается модель, снимаются команды и уничтожается окно.

Браузерный режим использует тот же `presentation.py` через `tools/preview_ui.py`. `?demo=1` допускает только источник `demo`, `?local=1` — собственную локальную историю. Без этих параметров приложение ожидает Gameface; автоматической подмены данных демо нет.

HTML содержит только собственные `app.js` и `app.css`. По [описанию загрузчика](https://gitlab.com/openwg/wot.gameface/-/blob/v1.2.2/resources/in/gui/gameface/js/index.js) нативная среда подключает `gui/gameface/js/index.js` и предоставляет `engine`, модель и окружение представления. Этот механизм требует проверки в конкретном клиенте. Код загрузчика и файлы игры в репозитории не копируются.

## Проверки и сборка

```powershell
python tools/generate_ui_fixtures.py --check
cd ui
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
cd ..
python tools/package_preview.py
python tools/build.py --python2 "C:\Python27\python.exe"
```

React 18.2.0 включён в сборку вместе с лицензиями зависимостей. TypeScript компилируется в один IIFE для ES2017; интерфейс не загружает CDN, внешние шрифты или игровые изображения. Flex-вёрстка и простые SVG уменьшают число предположений о возможностях движка, но не гарантируют совпадение браузера и Gameface.

В `.mtmod` находятся 12 Python-модулей, `Analytics.html`, JS, CSS, лицензии интерфейса, регистрация Layout и `meta.xml`. Внешний загрузчик остаётся отдельной зависимостью. CI-снимок экрана получен в Chromium на вымышленных данных; его нельзя использовать как доказательство работы в ангаре.

## Отключение и удаление

Для отключения окна закрой игру, поставь `"experimental_gameface_ui": false` и перезапусти клиент. Для удаления TankSession при закрытой игре удали только его `.mtmod`; историю можно сохранить. OpenWG Gameface может использоваться другими модами — удаляй его только с учётом их зависимостей и инструкции автора.
