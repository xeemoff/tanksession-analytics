# Данные, расчёты и команды — 2.0.0-rc2

Документ описывает реализованный контракт кандидата. **В RC1 часть полей проверена в игре; исправления RC2 требуют новой приёмки.** Наблюдения и расхождения приведены в [протоколе](CLIENT_VALIDATION_RU.md); инструкции — в [GAMEFACE_RU.md](GAMEFACE_RU.md).

## Schema 1 и совместимость истории

Каждый логический бой определяется `account_id` и `arena_id`. JSONL может содержать несколько дополняющих ревизий. Чтение объединяет их, сохраняя известные значения и первое время получения. Отдельное событие `additional_xp` разрешает только проверенную коррекцию опыта по правилам ниже. Старые строки не требуют переписывания.

| Поле | Тип / смысл |
|---|---|
| `schema` | Версия записи, 1 |
| `account_id`, `arena_id` | Локальные идентификаторы принадлежности и дедупликации; не входят в UI-снимок и новый CSV |
| `timestamp` | Первое время получения результата модом, Unix seconds; не начало боя |
| `vehicle`, `mode` | Сохранённая подпись техники и код режима; неизвестное обозначается `unknown` |
| `vehicle_id` | Необязательный ключ типа `type:<CD>` либо точного внутреннего имени `name:<nation:internal_name>`; это не ID сущности, аккаунта или боя |
| `vehicle_label` | Необязательная локализованная подпись точного типа, до 128 символов; без `vehicle_id` не принимается, не участвует в определении идентичности |
| `outcome` | `win`, `loss`, `draw`, `unknown` |
| `damage`, `xp` | Урон и полученный опыт; неотрицательное целое или `null` |
| `assistance_radio`, `assistance_track` | Известная помощь соответствующего типа либо `null` |
| `data_status` | Заново вычисленный `complete` / `incomplete` по исходу, урону и полученному опыту |
| `map` | Необязательная строка, в адаптере `arena:<arenaTypeID>`; ID типа арены, не отдельного боя |
| `map_label` | Необязательная локализованная подпись карты из справочника клиента, до 128 символов; без `map` не принимается |
| `vehicle_tier` | Необязательный уровень машины: целое 1–11 согласно справочному клиенту; не уровень боя |
| `vehicle_class` | `lightTank`, `mediumTank`, `heavyTank`, `AT-SPG`, `SPG` либо `null` |
| `vehicle_nation` | Подтверждённое пространство нации типа машины либо `null`; не страна игрока |
| `kills`, `shots`, `direct_hits`, `penetrations` | Необязательные неотрицательные целые счётчики |
| `survived` | `true`, `false` или `null`; числовой 0 не подменяет boolean |
| `xp_base` | Необязательная базовая строка опыта по проверяемому сопоставлению ниже |
| `xp_bonus` | Необязательный полученный опыт сверх базовой строки, неотрицательное целое либо `null` |
| `credits_gross` | Необязательное неотрицательное значение поля `credits` |
| `credits_net` | Необязательное знаковое целое: кредитный итог по полной формуле поддержанного сценария ниже |

Все новые поля необязательны. Старые записи получают `null`; известные нули сохраняются. `complete` не является оценкой полноты новых полей.

Числовые поля журнала ограничены 64-битным диапазоном. На границе JS действует предел точного целого `2**53 - 1`. Непригодные основные поля исключают запись из UI с диагностикой; слишком большие необязательные показатели скрываются без потери читаемых основных данных. Некорректная внешняя строка не переписывается.

### Идентичность техники и старые строки

`vehicle` сохраняет исходную подпись. `vehicle_id` хранит отдельно подтверждённую идентичность:

- `type:<CD>` — целочисленный компактный дескриптор типа машины. Для справочной версии проверяются тип предмета `vehicle`, нация, 16-битный индекс машины и отсутствие лишних старших битов. `playerVehicleID` — временный ID сущности и для этого поля не используется.
- `name:<nation:internal_name>` — точное внутреннее ресурсное имя, например `name:ussr:R04_T-34`. Оно служит отдельным запасным ключом до появления однозначной пары с типом.
- `null` — достоверного ключа нет. Свободная подпись, включая число в виде текста, сама по себе не считается дескриптором.

Чтение строит проекцию записей своего аккаунта. Точное внутреннее имя старой строки получает запасной ключ; связь имени или прежней подписи с числовым типом допускается только по непротиворечивым наблюдениям этого аккаунта. Регистр, похожее написание и перевод не выравниваются. Разные числовые типы с одной подписью не объединяются. Неоднозначная прежняя группа остаётся доступной в истории, но не подтверждает одну машину для сравнения прогресса и сессий.

Проекция не меняет исходные объекты журнала и JSONL. Подтверждённое дополнение конкретного боя может отдельно дописать ревизию: переход от имени к типу требует того же известного аккаунта и арены, согласованной нации и отсутствия противоречащих внутренних имён. Два разных числовых ID конфликтуют. При доказанной идентичности сохраняется первая подпись; известные показатели и первое время получения не заменяются.

Selector в интерфейсе — разрешённый `vehicle_id` либо оставшаяся прежняя подпись. Свободные подписи, начинающиеся с `type:`, `name:` или `legacy:`, получают отдельный `legacy:<SHA-256 подписи>`; они не пересекаются с настоящими ID. Это технический ключ выбора, а не определение новой машины или доказательство её типа.

### Метаданные карты и машины

В версии 2.0 адаптер получает уровень, класс и нацию из подтверждённого типа собственной машины. При входе в бой источник — `typeDescriptor.type`: поля `compactDescr`, `id`, `level`, `classTag` и `tags`. Числовой дескриптор должен совпасть с сохранённой идентичностью; доступная пара `id = (nationID, vehicleTypeID)` проверяется против его битов. Разные источники класса не объединяются, противоречащая нация не принимается. Перечень наций: `ussr`, `germany`, `usa`, `china`, `france`, `uk`, `japan`, `czech`, `sweden`, `poland`, `italy`, `intunion`.

Если метаданные не были захвачены при входе, после нормализации собственного результата можно запросить `items.vehicles.getVehicleType(typeCompDescr)`. Это поиск конкретного типа результата, а не чтение текущей выбранной машины ангара. Уже известные метаданные боя не заменяются поздним справочником. Ошибка необязательного справочника не отменяет сохранение основных показателей.

В RC2 отображаемая `vehicle_label` берётся из `VehicleType.shortUserString` или `userString`; исходная техническая `vehicle` и ключ типа сохраняются. Для старых строк с точным типом UI может добавить только подпись в копию данных: не более 128 уникальных типов за посещение ангара, от новых записей к старым. Это не массовое дописывание JSONL при открытии окна. Новые результаты сохраняют допустимую подпись обычным путём. [Поля локализованного типа](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/common/items/vehicles.py).

Имя карты читается из `ArenaType.g_cache[arenaTypeID].name` только при точном совпадении полного ID. Клиент строит ключ как `geometryID | (gameplayID << 16)`; маска только геометрии могла бы выбрать другую запись. Поле `name` уже проходит клиентскую локализацию. Неизвестная арена остаётся с ID и без придуманного названия. В проекте нет собственной таблицы соответствия карт.

Старые строки не получают уровень или класс сегодняшней версии машины задним числом. Поэтому срезы используют метаданные конкретных сохранённых результатов, а не распространяют последнюю карточку на всю историю. В списке выбора техники метаданные показываются, только когда известные значения группы согласованы; история может содержать разные подтверждённые уровни одной машины. Все отсутствующие значения образуют отдельную неизвестную группу.

### Базовый и бонусный опыт

```text
xp_base  = originalXP - achievementXP
xp_bonus = personal.xp - xp_base
```

Для каждой разности нужны известные корректные неотрицательные целые компоненты и неотрицательный результат. Отрицательная разность остаётся неизвестной, не обрезается до нуля. `xp_bonus` показывает полученный опыт сверх базовой строки после всех применённых корректировок. Это не сумма отдельных бустеров, опыта экипажа или свободного опыта. Метрики опыта не используются как доказательство изменения навыка.

### Применённый дополнительный опыт (2.0 RC2)

Обычный повтор результата по-прежнему не может менять известный опыт. Для дополнительного бонуса используется отдельная цепочка наблюдений: `IBattleResultsService.onResultPosted` → одна машина в `personal.xpProgress` → ожидаемый опыт и предложение `getAdditionalXPValue(arena)` → успешный флаг `isAddXPBonusApplied(arena)` после `PREMIUM_XP_BONUS_CHANGED`. `getVehicleForArena(arena).intCD` должен совпасть с типом этой машины. Проверяются собственный аккаунт, конкретная арена, поколение входа, отсутствие реплея и прежний опыт уже сохранённой записи. Мод не нажимает кнопку бонуса и не вызывает запрос его применения.

Подписки не зависят от `experimental_cache_recovery`. Наблюдаемые предложения ограничены 128 боями и текущим сеансом; неизвестное или противоречивое свидетельство не заменяется общим XP сессии. Конфликтующее предложение блокируется до следующего входа. До записи события предложения не сохраняются на диск, поэтому перезапуск между наблюдением и записью может оставить исходный XP. Если предложение не наблюдалось до применения, исходный опыт остаётся без догадок. В частности, бонус, применённый ещё до установки RC2, автоматически не восстанавливается.

В журнал дописывается отдельный объект:

```json
{"schema":1,"event":"additional_xp","source":"battle_results_service","account_id":"88","arena_id":"9001","vehicle_id":"type:257","xp_before":600,"xp_delta":450}
```

Идентификаторы в примере вымышленные. Событие принимается только для существующей записи с точным аккаунтом/ареной/типом и опытом `xp_before`; `xp_delta` должен быть положительным целым без переполнения. Повтор того же события — `duplicate`; отличающееся повторное свидетельство — `conflict`. Полученный XP увеличивается один раз, известный бонусный XP учитывает ту же прибавку; дата, остальные показатели и число боёв сохраняются. Повтор исходного результата распознаётся по сохранённой базе опыта. Другие известные расхождения продолжают отклонять всю обычную ревизию.

Читатель RC2 сводит событие и обычные строки в один логический бой; UI, CSV и C++-адаптер получают эффективные показатели. Компактирование сохраняет исходную базу и событие, а при необходимости — позднюю дополняющую строку после него. Оно не должно терять происхождение поправки или создавать отрицательный бонус при позднем заполнении неизвестных данных. Более старые читатели без поддержки `additional_xp` не учитывают новое событие; для правильных итогов после бонуса нужны мод и офлайн-инструменты RC2 или новее.

Сопоставление основано на закреплённом [сервисе итогов 1.46.0.0_CT](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/service.py), [персональном XP и его обновлении](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/reusable/personal.py) и [кэше предложений по арене](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/shared/utils/requesters/statsrequester.py). Автоматические тесты не доказывают идентичность API установленной игры.

### Чистые кредиты

В [economy.py](../src/res/scripts/client/gui/mods/tanksession_analytics/economy.py) реализована полная формула кредитного итога поддержанного сценария:

```text
draw       = round(originalCreditsToDraw * (appliedPremiumCreditsFactor100 / 100.0))
squad_draw = round(originalCreditsToDrawSquad * (premSquadCreditsFactor100 / 100.0))
events     = сумма кредитных значений personal.avatar.eventCreditsList
credits_net = credits - draw - squad_draw + events
              - autoRepairCost - autoLoadCost[0] - autoEquipCost[0]
```

Округление положительных компонентов воспроизводит Python 2.7, включая половины в сторону большего целого. Значения, для которых справочное вычисление с плавающей точкой теряет точность целых, отклоняются. В `credits` уже применены корректировки начислений; штрафы и бонусы не учитываются повторно.

Условия расчёта:

- код `bonusType` равен **1, 22 или 24**;
- в собственном результате ровно одна машина; если присутствует `rolloutsCount`, он корректен и не больше одного;
- `personal.avatar.accountDBID` подтверждён текущим собственным контекстом;
- все используемые компоненты явно известны, включая пустой список событий при отсутствии наград;
- коэффициент премиума положителен; нулевой коэффициент взводного компонента допустим, когда он известен;
- `autoLoadCost` содержит пару `(credits, gold)`, `autoEquipCost` — тройку `(credits, gold, crystal)`; берётся только кредитная часть.

Отсутствующий, повреждённый или несогласованный компонент оставляет `credits_net: null`. Известный отрицательный итог сохраняется. Расчёт учитывает фактически списанные кредиты; стоимость использованных складских предметов, золото, боны и будущие поступления из копилки в него не входят. Avatar-награды не распределяются между несколькими машинами или повторными выездами. Поддержка другого режима требует собственного подтверждённого сопоставления.

| `bonusType` | Справочный режим | `credits_net` в 2.0 |
|---|---|---|
| 1 | `REGULAR` | Известен только при выполнении всех перечисленных условий |
| 22 | `RANKED` | Тот же полный кредитный расчёт, при тех же условиях |
| 24 | `EPIC_RANDOM` | Известен только при выполнении всех перечисленных условий |
| Любой другой, отсутствующий или повреждённый | Не подтверждён этим сопоставлением | `null`; известное валовое начисление можно сохранить отдельно |

Для режима 22 проверена цепочка в том же pinned-коммите: [ranked-шаблон](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/templates/ranked_battles.py) клонирует `REGULAR_PERSONAL_STATS_BLOCK` и заменяет только компонент 8 с показателями машины. Компонент 6 — `TotalMoneyDetailsBlock` — остаётся из [regular-шаблона](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/templates/regular.py). [Composer](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/composer.py) связывает его с `ARENA_BONUS_TYPE.RANKED`; [фабрика](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/e241d4d04d610f0747271ff6f044ee809a607b53/source/res/scripts/client/gui/battle_results/reusable/__init__.py) использует общий `PersonalInfo`. Это обоснование программного сопоставления, а не заявление о проведённом живом ранговом бое или доступности этого режима на текущем сервере.

## Протокол UI 1

Базовый запрос:

```json
{
  "protocol": 1,
  "request_id": "ui:17",
  "vehicle": "name:ussr:R04_T-34",
  "window": 10,
  "page": 0,
  "history_query": "победа",
  "history_sort": "time_desc"
}
```

`vehicle: ""` означает всю технику своего аккаунта. `window` принимает 10, 30 или 100. `page` — нумерация с нуля, целое от 0 до 1 000 000; слишком большая существующая страница ограничивается последней доступной.

В `vehicle` передаётся selector из `vehicles[].name`. Необязательное `vehicles[].label` задаёт отображаемую подпись. Поля `vehicle_label` в истории, целях, разборе и группах техники также отделяют подпись от выбора. Прежний запрос с внутренним именем или свободной подписью поддерживается через точное однозначное разрешение своего аккаунта; по виду строки ID не угадывается.

Для интерфейса используется последняя известная подпись группы, в том числе в истории. Исходные подписи каждой записи сохраняются в JSONL и CSV. Если подписи разных selectors совпадают, выбор различается дополнительной пометкой: `#<числовой ID>`, «по имени» или «старая запись».

Разрешены только поля `protocol`, `request_id`, `vehicle`, `window`, `page`, `history_query`, `history_sort`, `action`, `preferences`, `goal`. Аккаунт, путь и имя выходного файла не принимаются. ID запроса содержит 1–64 ASCII-символа из букв, цифр, `_`, `.`, `:`, `-`.

`history_query` — буквальная подстрока до 64 символов без учёта регистра и внешних пробелов; регулярные выражения не выполняются. Поиск охватывает всю выбранную историю до пагинации: исходное и отображаемое название техники, selector, ID и имя карты, код класса/нации, исход и слова «победа», «поражение», «ничья», «неизвестно». Сортировки: `time_desc`, `time_asc`, `damage_desc`, `xp_desc`, `credits_desc`. Последняя использует знаковые чистые кредиты, `xp_desc` — полученный опыт. Для числовой сортировки известные значения идут по убыванию, неизвестные — в конце; равенство разрешается временем от нового к старому.

Поиск и сортировка изменяют только `history` и `pagination`. `pagination.total` — число найденных записей, поэтому может быть меньше `summary.battles`. Сводка, график, Coach, аналитика, отчёты и CSV по-прежнему относятся ко всей выбранной технике. При передаче одного из полей поиска страница по умолчанию равна нулю. Текущий запрос сохраняется для пассивного обновления окна, но строка поиска сама по себе в профиль не записывается.

JSON-команда ограничена 16 КиБ; дублирующиеся ключи, нечисловые константы, неверные типы и неизвестные поля отклоняются. Boolean не принимается вместо целого. Снимок ограничен 512 КиБ. Подтверждённый аккаунт задаёт Python-host и перепроверяет перед публикацией.

### Действия

| `action` | Дополнительные поля | Результат |
|---|---|---|
| Нет | Только выбор и страница | Новый снимок без записи |
| `initialize` | Нет | Восстановление фильтров профиля и снимок |
| `save_preferences` | `preferences` | Сохранение вида и стартовых фильтров |
| `save_goal` | `goal` | Создание или замена цели для пары техника/окно |
| `delete_goal` | `goal` без порога | Удаление цели для пары техника/окно |
| `export_csv` | Нет | Новый CSV всей выбранной истории |

Состав `preferences`:

```json
{
  "vehicle": "name:ussr:R04_T-34",
  "window": 10,
  "tab": "summary",
  "density": "compact",
  "contrast": "high",
  "theme": "hangar",
  "modules": ["metrics", "coach"],
  "motion": "system"
}
```

Вкладки: `progress`, `dynamics`, `history`, `summary`, `analytics`, `reports`, `settings`. Плотность: `normal` / `compact`; контраст: `standard` / `high`; тема: `hangar` / `slate` / `light`; движение: `system` / `reduced`. `modules` содержит выбранные уникальные значения из `metrics`, `coach`, `vehicle`, `chart`, `goals`, `activity`, `economy`, `reports`.

Пять прежних полей остаются обязательными. У старого профиля отсутствующие три новых поля получают в памяти значения `hangar`, `["metrics", "coach"]`, `system`. Чтение не переписывает файл. Значения сохраняются только по явной команде, переключение фильтра само по себе профиль не перезаписывает.

Цель:

```json
{"vehicle":"name:ussr:R04_T-34","window":30,"target_avg_damage":1000}
```

Порог — целое 1–50 000, окно цели — целое 10–1 000. Это отдельное окно цели, оно не обязано совпадать с переключателем сравнения 10/30/100. Для удаления передаются только `vehicle` и `window`. Максимум 30 целей.

### Расширения снимка

| Объект | Содержимое |
|---|---|
| `pagination` | `page`, `page_size: 5`, `pages`, `total`; присутствует при запросе с `page` |
| `metrics` | Средние дополнительных полей с числом наблюдений, выживаемость, точность, пробития и сводка до 12 ID карт |
| `sessions` | До семи последних выбранных сессий, основание `received_at`, разрыв 60 минут, статус сравнения |
| `workspace` | Возможность редактирования, предпочтения, видимые цели и результат явной операции |
| `coach` | Разбор двух полных окон одной машины и локальные рекорды |
| `insights` | До 24 отдельных результатов, серии, помощь, дни/техника и общий pending-счётчик аккаунта |
| `analytics` | Версия 1: срезы карты/уровня/класса/нации, UTC-активность и экономика техники |
| `reports` | Версия 1: последние 7 суток, 30 суток и вся полученная история с явными интервалами |

Новый запрос получает пять исторических записей с дополнительными полями на каждую страницу. Старый запрос без `page` сохраняет до 12 последних результатов с совместимыми дополнительными полями. Расширения необязательны для старых JSON-примеров; отсутствие `workspace` означает отсутствие редактирования.

Необязательные `xp_bonus` в деталях и `metrics.fields.xp_bonus` с `average`/`samples`, подписи `label`/`vehicle_label`, метаданные техники и `map_label` добавляются без смены протокола. Старые снимки без этих полей остаются допустимыми. Служебные ключи типа машины могут входить в selector и CSV; ID аккаунта и отдельного боя по-прежнему не передаются в UI.

Процент побед рассчитывается среди известных исходов. Для средней метрики учитываются только её известные значения. Точность — сумма прямых попаданий / сумма выстрелов по записям, где оба числа известны и `0 <= попадания <= выстрелы`. Для пробитий аналогично используются известные пробития и прямые попадания. Нулевой знаменатель даёт неизвестную долю.

`workspace.operation` сообщает успех или ошибку. Экспорт возвращает имя файла и число строк, без полного пути и идентификаторов. Ошибка источника очищает старый UI-снимок; локальная ошибка сохранения показывается отдельно от статистики.

## Срезы, календарь и экономика 2.0

`analytics.version = 1`, `basis = "received_at"`, `timezone = "UTC"`. Во всех срезах участвуют только проверенные записи подтверждённого аккаунта после выбора техники. Поиск по истории и размер окна Coach не меняют эту выборку.

Каждая группа имеет `key`, `label`, `summary` и `credits_net`. В группах техники может добавляться `vehicle_label`. `summary` — та же сводка с отдельными счётчиками известных исходов, урона и опыта. Ключ — средство группировки, подпись — текст интерфейса; ID отдельного боя или аккаунта в группах отсутствуют.

| Путь | Содержимое и границы |
|---|---|
| `dimensions.maps` | До 24 групп по полному ID карты; последняя группа при превышении лимита объединяет остаток |
| `dimensions.tiers` | До 12 групп: уровни 1–11 и неизвестное значение |
| `dimensions.classes` | До 6 групп: пять классов и неизвестное значение |
| `dimensions.nations` | До 13 групп: 12 пространств наций и неизвестное значение |
| `activity.days` | Ровно 90 последовательных UTC-дней, заканчивая днём `updated_at`; пустые дни присутствуют |
| `activity.weekdays` | Ровно 7 групп всей выбранной истории; ключи `0`–`6`, понедельник — 0 |
| `activity.hours` | Ровно 24 группы всей выбранной истории; ключи `00`–`23`, часы UTC |
| `economy.credits_gross`, `economy.credits_net`, `economy.xp_bonus` | Среднее, сумма и покрытие известными значениями |
| `economy.vehicles` | До 64 групп техники; остаток объединяется без потери количества боёв |
| `coverage` | Число записей с известными `map_label`, `vehicle_tier`, `vehicle_class`, `vehicle_nation` |

Группы срезов упорядочены по числу боёв по убыванию и ключу при равенстве. Ограничение размера включает группу «Остальные»: при большом числе карт показываются 23 группы и остаток. Его ключ обычно `other`; если такой ключ уже есть в данных, добавляется префикс `_` до получения свободного ключа. Сумма числа боёв по группам сохраняет исходную выборку. Неизвестное значение не исключается из знаменателя и не подменяется первой известной категорией.

Объект суммы имеет форму `{"samples": 2, "average": -150, "total": -300}`. `samples` считает только известные значения соответствующего поля. При отсутствии наблюдений возвращаются `samples: 0`, `average: null`, `total: null`; известные нули остаются нулями. Среднее округляется до одного десятичного знака, целая сумма сохраняется точно. Если сумма выходит за безопасный диапазон JS, `total` становится `null`, а допустимые число наблюдений и среднее остаются. Неполное покрытие означает сумму **известных** результатов, а не оценку полного дохода.

Календарь отражает время получения данных. Поздно восстановленный бой попадает в день восстановления; по этой шкале нельзя вычислить фактическое время игры, причины результата или рекомендовать «лучшее время суток». Для дня без боёв число боёв равно нулю, а средний урон и денежные наблюдения неизвестны. Группы дня недели и часа охватывают всю выбранную историю, поэтому их охват шире календарных 90 дней.

## Отчёты за периоды

`reports` содержит `version: 1`, `basis: "received_at"`, `timezone: "UTC"`, `excluded_future` и три элемента `periods`: `week`, `month`, `all_time`. Названия `week` и `month` означают **последние 7 и 30 суток**, а не календарные неделю и месяц. Интервалы явно передаются в Unix seconds как `[start_at, end_at)`.

Для снимка в целую секунду `now` граница `end_at = now + 1` включает результаты с `timestamp == now`. Предыдущий интервал имеет ту же длительность и заканчивается на `start_at`, не перекрывая текущий. Будущие записи не входят в отчёты; `excluded_future` сообщает их количество. Срезы всей истории и сам журнал при этом не переписываются. В `all_time` начало равно первому доступному timestamp либо `null`, если данных нет; `previous` отсутствует как `null`.

Каждый отчёт содержит `summary`, `credits_net`, `xp_bonus`, до 10 групп `vehicles`, `previous` и `comparison`. Сводка предыдущего периода включает точные границы, `summary` и `credits_net`. Группировка техники использует те же selectors и объединённый остаток, что аналитика.

| `comparison.status` | Условие |
|---|---|
| `insufficient_data` | Текущий или предыдущий интервал пуст; разницы неизвестны |
| `partial_data` | Оба интервала непусты, но урон или исходы известны не во всех записях |
| `ready` | Оба непусты, урон и исходы полностью известны |
| `not_applicable` | Вся история: предыдущий период не определён |

Минимум 10 боёв здесь не требуется: это описательный отчёт, а не Session Coach. Число наблюдений показано в сводке. `avg_damage_delta` существует только при полном покрытии уроном обоих интервалов; `win_rate_delta_pp` — при полностью известных исходах, в процентных пунктах. `credits_net_average_delta` требует полного покрытия чистыми кредитами обоих интервалов и допустимого числового диапазона. Поэтому при `partial_data` одна независимая разница может быть известной, а другая — `null`; статус `ready` не обещает известные кредиты.

Отчёты не выравнивают число боёв, режимы, составы команд и карты. Они показывают, что сохранено за указанные интервалы, и не доказывают изменение навыка или причинную связь.

## Очередь и жизненный цикл

Просмотр объединяется с задержкой 150 мс: сохраняется последний выбор. Явные мутации проходят ограниченную очередь до 16 команд с сохранением порядка. Они не исчезают из-за следующего изменения фильтра. Старый ожидающий запрос просмотра не заменяет актуальный ID команды.

Автоматическое обновление после сохранения/экспорта повторяет только чтение. Ограниченный кэш выполненных команд защищает от повторной доставки в текущем открытии; это не обещание вечной дедупликации после нового запуска процесса.

Frontend принимает ответ только для актуального `request_id`. Смена аккаунта, выход из ангара или закрытие окна отменяют ожидающие обращения. Контроль контекста выполняется каждые 0,5 с без перечитывания журнала.

## Сессии и ограничения сравнения

Группировка выполняется в хронологической истории одного аккаунта **до выбора техники**. Игра на другой машине между двумя результатами может сохранять общую сессию. Разрыв в получении результатов минимум 3 600 секунд начинает новую группу.

Затем применяется фильтр машины. Сравниваются две последние группы, где есть выбранные результаты. Для состояния `ready` нужны:

- одна известная машина;
- минимум 10 записей в каждой группе;
- известный урон каждой записи;
- один и тот же известный режим, без `unknown` и кода `0`.

До этого показываются состояния выбора машины, недостаточной выборки, неполноты или несовместимости режимов. Среднее и медиана описывают сохранённые результаты. Это не оценка причин, уровня навыка, усталости или фактической длительности игры. Поздно полученный результат может изменить границу сессии относительно реальных боёв.

Состояние `identity_ambiguous` в целях, Session Coach и сравнении сессий означает, что одна прежняя подпись связана с разными типами, а конкретная принадлежность старых строк не доказана. История не удаляется; новые рекорды, достижения цели и сравнение одной машины для этой группы не объявляются.

## Профиль и legacy-цели

Профиль: `mods/configs/tanksession_analytics/profiles/<SHA-256 аккаунта>.json`. Новое явное сохранение записывает `version: 2`, `preferences` и `goals`; чтение прежней версии 1 поддерживается без перезаписи. Для настроек и целей версии 1 точная старая подпись имеет приоритет при совпадении с новым пространством ключей, а версия 2 сохраняет канонический selector. Предыдущие байты профиля остаются в `.bak`. Версия журнала и протокола UI остаётся 1.

`goals: null` означает наследование видимых целей старого `goals.json`. Собственный список заменяет наследование; `[]` означает отсутствие целей. Первое сохранение или удаление цели формирует список профиля. Старый файл читается только при необходимости и не переписывается.

Новые предпочтения и цели сохраняют selector машины. Прежние строковые ключи разрешаются по той же проекции своего аккаунта; неоднозначный alias не превращается в произвольно выбранный тип. Чтение не переписывает профиль, legacy-цели или историю. Сохранение остаётся явной пользовательской командой.

Корректный собственный список не зависит от доступности legacy-файла. При ошибке необходимого профиля/legacy-источника окно сообщает `read_failed`, оставляет доступное чтение статистики и не сохраняет поверх повреждённых данных.

Запись выполняется через временный файл, `flush`, `fsync` и доступный API замены (`os.replace` или `MoveFileExW`). При отсутствии Windows `ctypes` используется последовательность переименований: прежний файл → `.rollback`, временный → основной, затем удаление `.rollback`. Ошибка установки нового файла вызывает попытку вернуть прежний; после прерывания при отсутствующем основном файле восстанавливается только ограниченная копия, прошедшая валидацию профиля. Валидный существующий основной файл означает завершённую запись. Повреждённый существующий файл не перезаписывается копией молча: обе версии сохраняются, возвращается `read_failed`.

Предыдущий профиль сохраняется в `.bak` с такими же правилами замены. Fallback рассчитан на одного писателя и не обещает атомарность всей последовательности, одновременную запись несколькими процессами или защиту от повреждения носителя. Отказ записи возвращает `operation.code: write_failed` вместе с доступной историей и прежними настройками; `ImportError` не превращает всю панель в `data_unavailable`. Ограничения: 64 КиБ на профиль и до 64 файлов профилей. Это локальное хранение, не шифрование и не облачная синхронизация.

В браузерном режиме «только чтение» запрещены также восстановительные записи. Если основной профиль отсутствует, валидный `.rollback` можно прочитать как временный источник без переименования или удаления файлов. `can_edit` остаётся `false`; Workspace отдельно запрещает сохранение и экспорт. Фактическое восстановление выполняется в игре либо после явного `--allow-write` для Preview.

## CSV и браузерные команды

Экспорт использует всю выбранную историю своего аккаунта, максимум 100 000 строк. Окно 10/30/100, страница и поиск истории не ограничивают его. При пустом фильтре техники экспортируется вся техника. Пустая история и превышение лимита дают явную ошибку.

Файл создаётся с уникальным именем в `exports/` рядом с журналом. Формат: UTF-8 с BOM, `;`, строки CRLF, значения в кавычках. Включены исходная подпись `vehicle`, необязательный `vehicle_id`, `map_label`, уровень/класс/нация техники, `xp_base`, `xp_bonus` и известные кредитные показатели. Неизвестное — пустая ячейка, выживание — 1/0. Текстовые ячейки защищены от интерпретации как формул. Числовой отрицательный чистый доход остаётся числом. ID аккаунта и боя не включаются; `timestamp` сохраняет смысл первого получения.

Для собственной истории браузер по умолчанию только читает. `--allow-write` разрешает сохранение профиля, целей и CSV рядом с выбранным журналом. Демонстрация использует временную папку и не меняет исходные примеры.

Записывающий HTTP-запрос: `POST /api/command`, `Content-Type: application/json`, `X-TankSession-Request: 1`. Проверяются Host/Origin и размер тела; CORS не открывается, сервер слушает loopback. GET не выполняет мутации. Аккаунт закреплён параметром запуска и не принимается из HTTP.
