# Данные, расчёты и команды — 1.0.0-rc1

Документ описывает реализованный контракт кандидата. **Новые поля и нативные команды ещё не проверены в установленном клиенте.** Исторические игровые наблюдения приведены в [протоколе](CLIENT_VALIDATION_RU.md); инструкции — в [GAMEFACE_RU.md](GAMEFACE_RU.md).

## Schema 1 и совместимость истории

Каждый логический бой определяется `account_id` и `arena_id`. JSONL может содержать несколько дополняющих ревизий. Чтение объединяет их, сохраняя известные значения и первое время получения. Старые строки не требуют переписывания.

| Поле | Тип / смысл |
|---|---|
| `schema` | Версия записи, 1 |
| `account_id`, `arena_id` | Локальные идентификаторы принадлежности и дедупликации; не входят в UI-снимок и новый CSV |
| `timestamp` | Первое время получения результата модом, Unix seconds; не начало боя |
| `vehicle`, `mode` | Сохранённая строка техники и код режима; неизвестное обозначается `unknown` |
| `outcome` | `win`, `loss`, `draw`, `unknown` |
| `damage`, `xp` | Урон и полученный опыт; неотрицательное целое или `null` |
| `assistance_radio`, `assistance_track` | Известная помощь соответствующего типа либо `null` |
| `data_status` | Заново вычисленный `complete` / `incomplete` по исходу, урону и полученному опыту |
| `map` | Необязательная строка, в адаптере `arena:<arenaTypeID>`; ID типа арены, не отдельного боя |
| `kills`, `shots`, `direct_hits`, `penetrations` | Необязательные неотрицательные целые счётчики |
| `survived` | `true`, `false` или `null`; числовой 0 не подменяет boolean |
| `xp_base` | Необязательная базовая строка опыта по проверяемому сопоставлению ниже |
| `credits_gross` | Необязательное неотрицательное значение поля `credits` |
| `credits_net` | Необязательное знаковое целое для нормализованного импорта; адаптер игры не вычисляет |

Все новые поля необязательны. Старые записи получают `null`; известные нули сохраняются. `complete` не является оценкой полноты новых полей.

Числовые поля журнала ограничены 64-битным диапазоном. На границе JS действует предел точного целого `2**53 - 1`. Непригодные основные поля исключают запись из UI с диагностикой; слишком большие необязательные показатели скрываются без потери читаемых основных данных. Некорректная внешняя строка не переписывается.

### Сопоставление полей клиента

| Поле результата | Поле журнала | Условие |
|---|---|---|
| `common.arenaTypeID` | `map` | Положительное целое, строка вида `arena:11` |
| `personal.kills` | `kills` | Корректное неотрицательное целое |
| `personal.shots` | `shots` | То же |
| `personal.directHits` | `direct_hits` | То же |
| `personal.piercings` | `penetrations` | То же |
| `personal.deathReason` | `survived` | `-1` → `true`, `>=0` → `false`; остальное неизвестно |
| `personal.originalXP`, `personal.achievementXP` | `xp_base` | Оба известных корректных неотрицательных целых; разность неотрицательна |
| `personal.credits` | `credits_gross` | Корректное неотрицательное целое |
| Полного проверенного источника нет | `credits_net` | В игровом результате всегда `null` |

`personal` в таблице означает выбранную собственную запись, а не произвольного участника. Полученный `xp` не делится на предположительный премиум-множитель. Отсутствующий `achievementXP` не считается нулём.

Сопоставление основано на справочных [описаниях полей](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/1.46/source/res/scripts/common/battle_results/battle_results_common.py), [константах](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/1.46/source/res/scripts/common/constants.py), [отображении состояния](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/1.46/source/res/scripts/client/gui/battle_results/components/personal.py) и [расчёте строки опыта](https://github.com/StranikS-Scan/WorldOfTanks-Decompiled/blob/1.46/source/res/scripts/client/gui/battle_results/components/details.py) ветки 1.46. Это не подтверждение тождественности установленному клиенту.

## Протокол UI 1

Базовый запрос:

```json
{
  "protocol": 1,
  "request_id": "ui:17",
  "vehicle": "ussr:R04_T-34",
  "window": 10,
  "page": 0
}
```

`vehicle: ""` означает всю технику своего аккаунта. `window` принимает 10, 30 или 100. `page` — нумерация с нуля, целое от 0 до 1 000 000; слишком большая существующая страница ограничивается последней доступной.

Разрешены только поля `protocol`, `request_id`, `vehicle`, `window`, `page`, `action`, `preferences`, `goal`. Аккаунт, путь и имя выходного файла не принимаются. ID запроса содержит 1–64 ASCII-символа из букв, цифр, `_`, `.`, `:`, `-`.

JSON-команда ограничена 16 КиБ; дублирующиеся ключи, нечисловые константы, неверные типы и неизвестные поля отклоняются. Boolean не принимается вместо целого. Снимок ограничен 512 КиБ. Подтверждённый аккаунт задаёт Python-host и перепроверяет перед публикацией.

### Действия

| `action` | Дополнительные поля | Результат |
|---|---|---|
| Нет | Только выбор и страница | Новый снимок без записи |
| `initialize` | Нет | Восстановление фильтров профиля и снимок |
| `save_preferences` | `preferences` | Сохранение вида и стартовых фильтров |
| `save_goal` | `goal` | Создание или замена цели для пары техника/окно |
| `delete_goal` | `goal` без порога | Удаление цели для пары техника/окно |
| `export_csv` | Нет | Новый CSV всей выбранной истории |

Состав `preferences` фиксирован:

```json
{
  "vehicle": "ussr:R04_T-34",
  "window": 10,
  "tab": "summary",
  "density": "compact",
  "contrast": "high"
}
```

Вкладки: `progress`, `dynamics`, `history`, `summary`, `settings`. Плотность: `normal` / `compact`. Контраст: `standard` / `high`. Значения сохраняются только по явной команде, переключение фильтра само по себе профиль не перезаписывает.

Цель:

```json
{"vehicle":"ussr:R04_T-34","window":30,"target_avg_damage":1000}
```

Порог — целое 1–50 000, окно цели — целое 10–1 000. Это отдельное окно цели, оно не обязано совпадать с переключателем сравнения 10/30/100. Для удаления передаются только `vehicle` и `window`. Максимум 30 целей.

### Расширения снимка

| Объект | Содержимое |
|---|---|
| `pagination` | `page`, `page_size: 5`, `pages`, `total`; присутствует при запросе с `page` |
| `metrics` | Средние дополнительных полей с числом наблюдений, выживаемость, точность, пробития и сводка до 12 ID карт |
| `sessions` | До семи последних выбранных сессий, основание `received_at`, разрыв 60 минут, статус сравнения |
| `workspace` | Возможность редактирования, предпочтения, видимые цели и результат явной операции |
| `coach` | Разбор двух полных окон одной машины и локальные рекорды |
| `insights` | До 24 отдельных результатов, серии, помощь, дни/техника и общий pending-счётчик аккаунта |

Новый запрос получает пять исторических записей с дополнительными полями на каждую страницу. Старый запрос без `page` сохраняет до 12 последних результатов в прежнем виде. Расширения необязательны для старых JSON-примеров; отсутствие `workspace` означает отсутствие редактирования.

Процент побед рассчитывается среди известных исходов. Для средней метрики учитываются только её известные значения. Точность — сумма прямых попаданий / сумма выстрелов по записям, где оба числа известны и `0 <= попадания <= выстрелы`. Для пробитий аналогично используются известные пробития и прямые попадания. Нулевой знаменатель даёт неизвестную долю.

`workspace.operation` сообщает успех или ошибку. Экспорт возвращает имя файла и число строк, без полного пути и идентификаторов. Ошибка источника очищает старый UI-снимок; локальная ошибка сохранения показывается отдельно от статистики.

## Очередь и жизненный цикл

Просмотр объединяется с задержкой 150 мс: сохраняется последний выбор. Явные мутации проходят ограниченную очередь до 16 команд с сохранением порядка. Они не исчезают из-за следующего изменения фильтра. Старый ожидающий запрос просмотра не заменяет актуальный ID команды.

Автоматическое обновление после сохранения/экспорта повторяет только чтение. Ограниченный кэш выполненных команд защищает от повторной доставки в текущем открытии; это не обещание вечной дедупликации после нового запуска процесса.

Frontend принимает ответ только для актуального `request_id`. Смена аккаунта, выход из ангара или закрытие окна отменяют ожидающие обращения. Контроль контекста выполняется каждые 0,5 с без перечитывания журнала.

## Сессии и ограничения сравнения

Группировка выполняется в хронологической истории одного аккаунта **до выбора техники**. Игра на другой машине между двумя результатами может сохранять общую сессию. Разрыв в получении результатов минимум 3 600 секунд начинает новую группу.

Затем применяется фильтр машины. Сравниваются две последние группы, где есть выбранные результаты. Для состояния `ready` нужны:

- одна известная машина;
- минимум 10 записей в каждой группе;
- известный урон каждой записи;
- один и тот же известный режим, без `unknown` и кода `0`.

До этого показываются состояния выбора машины, недостаточной выборки, неполноты или несовместимости режимов. Среднее и медиана описывают сохранённые результаты. Это не оценка причин, уровня навыка, усталости или фактической длительности игры. Поздно полученный результат может изменить границу сессии относительно реальных боёв.

## Профиль и legacy-цели

Профиль: `mods/configs/tanksession_analytics/profiles/<SHA-256 аккаунта>.json`. Формат содержит `version: 1`, `preferences` и `goals`.

`goals: null` означает наследование видимых целей старого `goals.json`. Собственный список заменяет наследование; `[]` означает отсутствие целей. Первое сохранение или удаление цели формирует список профиля. Старый файл читается только при необходимости и не переписывается.

Корректный собственный список не зависит от доступности legacy-файла. При ошибке необходимого профиля/legacy-источника окно сообщает `read_failed`, оставляет доступное чтение статистики и не сохраняет поверх повреждённых данных.

Запись выполняется через временный файл, `flush`, `fsync` и атомарную замену. Предыдущий профиль сохраняется в `.bak`. Ограничения: 64 КиБ на профиль и до 64 файлов профилей. Это локальное хранение, не шифрование и не облачная синхронизация.

## CSV и браузерные команды

Экспорт использует всю выбранную историю своего аккаунта, максимум 100 000 строк. Окно 10/30/100 и страница не ограничивают его. При пустом фильтре экспортируется вся техника. Пустая история и превышение лимита дают явную ошибку.

Файл создаётся с уникальным именем в `exports/` рядом с журналом. Формат: UTF-8 с BOM, `;`, строки CRLF, значения в кавычках. Неизвестное — пустая ячейка, выживание — 1/0. Текстовые ячейки защищены от интерпретации как формул. Числовой отрицательный чистый доход остаётся числом. ID аккаунта и боя не включаются; `timestamp` сохраняет смысл первого получения.

Для собственной истории браузер по умолчанию только читает. `--allow-write` разрешает сохранение профиля, целей и CSV рядом с выбранным журналом. Демонстрация использует временную папку и не меняет исходные примеры.

Записывающий HTTP-запрос: `POST /api/command`, `Content-Type: application/json`, `X-TankSession-Request: 1`. Проверяются Host/Origin и размер тела; CORS не открывается, сервер слушает loopback. GET не выполняет мутации. Аккаунт закреплён параметром запуска и не принимается из HTTP.
