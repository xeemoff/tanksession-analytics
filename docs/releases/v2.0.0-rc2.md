# TankSession Analytics 2.0.0-rc2

Кандидат с исправлениями по частичному испытанию RC1 на клиенте «Мира танков» **1.46.0.0**. Оператор подтвердил точный SHA-256 установленного RC1; наблюдения сохранены в [игровом протоколе](https://github.com/xeemoff/tanksession-analytics/blob/v2.0.0-rc2/docs/CLIENT_VALIDATION_RU.md). RC2 требует нового испытания в игре, стабильный **2.0.0** пока не принят.

## Исправления

- Сохранение настроек и целей больше не требует наличия `ctypes` во встроенном Python. При отсутствии доступного атомарного API используется последовательность переименований с проверяемой копией для восстановления. Ошибка операции показывается вместе с доступной историей, не заменяя всю панель экраном недоступности данных.
- Для Gameface добавлены обработка направления и шага колеса, явные цвета, шрифты и состояния кнопок. В истории устранены конкурирующие ограничения высоты и разбиение счётчика страницы; нижние кнопки прокрутки позволяют добраться до длинных разделов.
- Подпись техники берётся из локализованного описания точного типа машины. Ключ идентичности сохраняется; похожие названия не объединяют разные машины.
- Дополнительный опыт после применения бонуса обрабатывается отдельно от обычного повторного результата: нужны наблюдённые данные именно этого аккаунта, боя и машины и подтверждение применения бонуса. Коррекция добавляется в журнал отдельным событием, а число логических боёв не растёт.
- В документации зафиксированы реальные результаты RC1, обнаруженные ошибки и последовательность новой проверки. Старые ответы кэша `not_available` не выдаются за восстановленные бои.

## Ограничения

Обработчик дополнительного опыта рассчитан на новый бой, для которого мод наблюдал необходимые данные **до** применения бонуса. Уже применённый до установки бонус RC1 не восстанавливается из агрегатов сессии. Обычный конфликт известных чисел по-прежнему не разрешается произвольной перезаписью.

Время первого получения результата, календарь и интервалы аналитики сохраняют прежний смысл; календарные группы подписаны UTC. Неполные старые записи не получают придуманные метаданные.

Автоматические проверки подтверждают сценарии с контролируемыми входами. Направление физического колеса, фактический вид и сигналы установленной игры нужно проверить в Gameface. Подробные результаты CI публикуются в [отчёте готовности](https://github.com/xeemoff/tanksession-analytics/blob/v2.0.0-rc2/docs/READINESS_2_0_0_RU.md). Все 13 обязательных проверок стабильного выпуска остаются открытыми до отдельной приёмки точного пакета.

## Установка и первая проверка

1. Закрой игру, распакуй весь `TankSession_Analytics_2.0.0-rc2_Windows.zip`, запусти `manager.cmd`, выбери папку и точную версию клиента, нажми «Установить / обновить». Каталог истории `mods/configs/tanksession_analytics/` сохраняется.
2. В игре открой F8 → «Настройки», сохрани высокий контраст, закрой и открой окно. Должны сохраниться выбранный вид и доступ к истории. Затем проверь колесо в обе стороны и нижние разделы.

После этого проверяются полный перезапуск, цель, подпись машины и дополнительный опыт на новом бое. [Полный план](https://github.com/xeemoff/tanksession-analytics/blob/v2.0.0-rc2/docs/CHECK_CLIENT_RU.md).

## Файлы выпуска

- `.mtmod` и `.sha256` — пакет для ручной установки.
- `Windows.zip` и `.sha256` — пакет, графический менеджер и инструкции; Python и Node.js для установки не нужны.
- `Preview.zip` и `.sha256` — браузерный просмотр; нужен Python 3.9+.
- `Native_Windows_x64.zip` / `Native_Linux_x64.zip` и их `.sha256` — отдельный C++23-движок с Python 3-адаптером для офлайн-отчётов.

OpenWG Gameface устанавливается отдельно; для окна нужна настройка `experimental_gameface_ui`. Дополнительный UI и восстановление через кэш по умолчанию выключены. Обработка подтверждённого дополнительного опыта не зависит от включения экспериментального восстановления.
