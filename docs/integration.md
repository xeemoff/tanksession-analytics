## Границы проверки

| Уровень | Что проверяет | Чего не доказывает |
|---|---|---|
| Python 3 unit и HTTP tests | Расчёты, цели, записи, loopback-запросы, CSV, имитацию событий | Совместимость клиента |
| Runtime чистых модулей на CPython 2.7 | Выполнение нормализации, Unicode, ревизий и целей | Сигнатуры игровых событий |
| Настоящая сборка `.mtmod` | Компиляцию, состав, code objects собственного кода, воспроизводимость | Загрузку пакета игрой |
| `--verify` | Структуру, метаданные, CRC, заголовки | Поведение произвольного байткода |
| Проверка на своём клиенте | Фактическую загрузку и результат конкретных сценариев | Совместимость с будущими патчами |

Для первых трёх уровней смотри успешность CI **нужного коммита**. Пятый уровень пока не подтверждён.

## Предположения адаптера

`game.py` использует `BigWorld`, `PlayerEvents`, `BattleReplay` и предполагаемые события результатов, входа в аккаунт и готовности аватара. Имена, аргументы callback, расположение идентификаторов и значения полей должны быть сверены в установленной версии клиента. При недоступной проверке replay адаптер прекращает сбор и пишет диагностическое сообщение.

Корень игры определяется по `paths.xml` в рабочем каталоге или кандидате `ResMgr.appDirectory()`. Само наличие этих API и реальный путь записи проверяются в игре. При ошибке запуска лог содержит стадию и класс исключения. Полный путь журнала виден локально после успешной инициализации.

## Получение результата

Контекст начала своего боя сохраняется в pending-журнал. Событие результата проходит проверку аккаунта и арены, нормализацию, проверку schema 1 и `BattleStore.upsert`.

Основные статусы: `saved`, `updated`, `duplicate`, `conflict`. `complete` означает только известные исход, урон и опыт. Необязательная помощь союзникам может оставаться неизвестной. Ожидание снимается после сохранения полных основных показателей; конфликт и неполный результат не закрывают его.

Повторный результат заполняет отсутствующие поля. Он не меняет известные показатели и первое время получения. При противоречии новая ревизия отклоняется целиком. Старые записи с неопределённым аккаунтом не переатрибутируются автоматически.

## Экспериментальный кэш

Восстановление **выключено по умолчанию**. Оно предполагает интерфейс `battleResultsCache.get(arena_uid, callback)` и `callback(error_code, result)`. Это предположение текущего адаптера, а не подтверждённый контракт актуальной игры.

Только после проверки API в фактической папке `mods/configs/tanksession_analytics/` можно создать `settings.json`:

```json
{"experimental_cache_recovery": true}
```

Одна попытка обработки делает максимум пять вызовов, включая вызовы с исключением. Между попытками одного боя выдерживается интервал; потерянный ответ допускает повтор после тайм-аута. Токены запроса и входа не позволяют старому callback обработать результат нового ожидания. При смене аккаунта и остановке мода ожидания инвалидируются. Обращения ограничены сохранёнными контекстами своего аккаунта, полного импорта истории нет.

После проверки можно вновь установить `false` и перезапустить клиент. Не используй включение кэша как обход ошибки основного пути.

## Известные ограничения

- Игровой загрузчик, версия встроенного интерпретатора, события и реальные поля ещё требуют подтверждения.
- Название техники пока служит ключом цели; стабильный игровой ID ещё не подтверждён.
- `timestamp` — первое время получения результата. Поздно полученный бой может попасть в другой день относительно его фактического начала.
- Изменение уже известной метрики не разрешается автоматически. Конфликт требует анализа, оригинальная запись сохраняется.
- JSONL рассчитан на один процесс записи. Offline-компактирование с резервной копией реализовано; межпроцессных транзакций и миграции будущих схем нет.
- Панель — отдельное приложение в браузере. Встроенного Gameface/React-экрана нет.
- Если клиент не предоставил результат, достоверно восстановить его невозможно.

После обновления клиента повторяй испытания. Правила распространения и ссылки на действующие условия находятся в [PUBLICATION_RU.md](PUBLICATION_RU.md).
