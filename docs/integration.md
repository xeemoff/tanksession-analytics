# Проверка интеграции с клиентом «Мира танков» — v0.4.0-rc2

> **Не выполнено на реальном клиенте.** Не утверждай, что мод работает с текущей игрой, пока не пройдёшь проверку ниже. Это план испытаний, а не подтверждение совместимости или разрешение от Lesta Games.

## Дополнение v0.4.0-rc2

Подробные пошаговые инструкции, новые коды диагностики и правила безопасной передачи счётчиков есть в [CHECK_CLIENT_RU.md](CHECK_CLIENT_RU.md). Игровой адаптер теперь требует подтверждённую личность аккаунта и не связывает отложенный результат с другим аккаунтом. В `meta.xml` применён рекомендуемый корень `<root>`. Всё это проверено **только тестами на имитации**.

## Что проверено локально

- Статистика, фильтры, хранение JSONL, защита от дублей и работа с пропусками на синтетических данных.
- Подписка и отписка игрового адаптера на имитации `BigWorld`, `PlayerEvents` и `BattleReplay`.
- Симуляция отложенных ответов кэша и сохранения контекста незавершённого боя.
- Панель в браузере на localhost, сравнения и экспорт CSV.

**Не проверено:** настоящие игровые события и данные, API `battleResultsCache`, сборка с Python 2.7 в этой среде, настоящая работа UI в ангаре и поведение в игре.

## Перед первым запуском

1. Ознакомься с [официальными правилами запрещённых модификаций](https://lesta.ru/support/ru/products/mt/article/15152/). Мод рассчитан **только на послебоевую статистику**, без изменения игровой механики.
2. Сделай резервную копию игровых файлов и временно отключи другие моды, чтобы исключить конфликты.
3. Установи Python 3.9+ для анализа и выполни `python -m unittest discover -s tests -v` и `python tools/simulate_capture.py`.
4. Для пробной сборки используй отдельный Python 2.7: `python tools/build.py --python2 "C:\Python27\python.exe"`. **Не компилируй игровой код под Python 3**, если клиент использует Python 2.7.
5. Проверь **действующую** папку модов по своей версии клиента. При выключенной игре положи созданный `.mtmod` в соответствующий каталог `mods/<версия>/`; не перезаписывай чужие файлы. Ориентир: [сообщество моддинга — формат `.mtmod`](https://forum.tanki.su/topic/2204726-mtmod/).
6. Не включай экспериментальное восстановление кэша: оно по умолчанию отключено.

## Проверка обычного результата боя

1. Запусти игру и найди `python.log`. Ищи `[TankSession] Started; local data path: ...`. Если строки нет, проверь загрузчик и пути импорта.
2. Войди в обычный бой. Проверь событие `Staged own battle for delayed-result recovery`. При отсутствии — выясни, доступно ли `onAvatarReady` и где клиент хранит `arenaUniqueID`.
3. Дождись официальных итогов боя. В логе должна появиться строка `Saved battle: <arenaID>` и новая запись в `battles.jsonl`.
4. Сверь результаты с итоговым экраном игры: танк, победа/поражение/ничья, урон, опыт. Проверь корректную привязку к собственному аккаунту. Неизвестные показатели не должны подменяться нулями.
5. Перезапусти игру, проверь, что запись сохранилась, а повторный callback не создаёт дубль.
6. Запусти `python tools/dashboard.py --data "<точный путь из лога>"`; проверь фильтры, сравнения и CSV. Доступ открыт только по localhost.
7. Выключи мод и убедись, что клиент работает без него.

## Экспериментальное восстановление результата после досрочного выхода

**По умолчанию только хранится снимок контекста.** Это ещё не означает, что пропущенный результат будет получен автоматически.

Для функции восстановления сначала проверь API в своей версии клиента и сигнатуру callback. Один старый пример сообщества (2021) использует `BigWorld.player().battleResultsCache.get(arenaUniqueID, callback)` с `callback(errorCode, result)`: [материал сообщества](https://koreanrandom.com/forum/topic/62395-%D1%81%D0%B1%D0%BE%D1%80-%D1%81%D1%82%D0%B0%D1%82%D0%B8%D1%81%D1%82%D0%B8%D0%BA%D0%B8-%D0%BE-%D0%BF%D0%BE%D0%BF%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D1%8F%D1%85/page/3/). Этот пример может быть устаревшим. Не следует заменять проверку API вмешательством в клиент или сбором чужих данных.

После подтверждения совместимости при выключенной игре создай `mods/configs/tanksession_analytics/settings.json` **в фактическом корне игры**, который использует адаптер:

```json
{"experimental_cache_recovery": true}
```

После перезапуска найди в логе строку `EXPERIMENTAL cache recovery enabled`. Проверь один обычный бой с досрочным выходом: после появления итогового результата в игре попробуй обнаружить `Recovered battle: <arenaID>`; затем обязательно сверь запись с итогами. Не менее чем на 20 обычных боях отдельно проверь повторы, выходы из аккаунта и несоответствие ID арены. Если есть сомнения, установи `false` и перезапусти игру.

Экспериментальная очередь делает не более пяти запросов за событие входа в ангар, использует интервал повторов около 15 секунд и привязывает обращения к идентифицированному аккаунту. Полный импорт истории не предусмотрен.

## Конфиденциальность, устранение проблем и удаление

- Идентификатор аккаунта не является паролем, но представляет личные данные. Не публикуй реальные JSONL, `settings.json`, ID аккаунта или полные игровые логи.
- Используй **фактический путь из лога**: рабочий каталог игры может отличаться от ожидаемого.
- Для удаления выключи игру и удали только `ru.tanksession.analytics_0.4.0-rc2.mtmod` из каталога соответствующей версии; пользовательскую историю удаляй отдельно **только по своему желанию**.
- При обновлении игрового клиента проведи все проверки заново.

## Известные инженерные ограничения

1. Устаревший Python 2.7 и упаковка байткода не проверены в текущем окружении.
2. Реальные структуры событий и ID техники могут отличаться; неоднозначные данные пропускаются.
3. Если результат не пришёл ни через событие, ни из кэша, восстановить его достоверно нельзя.
4. JSONL рассчитан на один процесс; компактирование и миграция схемы ещё не реализованы.
5. `timestamp` означает время **получения результата**, а не начала боя.
6. Отдельная веб-панель ещё не интегрирована в ангар через Gameface/React.
