# Проверка готовности к 1.0.0

Дата: **26 ноября 2026**. Предмет проверки: код кандидата **1.0.0-rc1**, доставка, автоматические проверки и фактические игровые испытания.

## Вывод

**Стабильная 1.0.0 пока не готова.** Основная программная часть кандидата реализована. Для завершения исходного плана остаются отдельные функции, проверка точного пакета в игре и выпуск. Успешные тесты браузера и Python не заменяют проверку установленного клиента.

При повторной проверке найдены 65 подготовленных файлов, которые оставались только в рабочем каталоге предыдущего чата. Они сохранены без изменения содержимого в ветке `release/v1.0.0-rc1`, [коммит 6f657a4](https://github.com/xeemoff/tanksession-analytics/commit/6f657a46af640f07795ae4e009ea9b189d383461). Локальное и удалённое дерево совпали: `383aaf378b847a23dee5cd4ef5dc20603e7144a1`.

Предыдущее утверждение, что история, настройки, цели и сравнение сессий ещё не написаны, было неполным: они отсутствовали на GitHub, но сохранились локально. Отдельный [PR #5](https://github.com/xeemoff/tanksession-analytics/pull/5) решает часть задачи отложенных результатов; кандидат содержит собственное более широкое исправление. Оба решения нельзя механически накладывать друг на друга.

## Найденные проблемы и исправления

Первый CI именно найденного кандидата: [45863618520](https://github.com/xeemoff/tanksession-analytics/actions/runs/45863618520).

- **Установщик Windows:** два положительных сценария упали из-за недоступного `Get-FileHash` при запуске Windows PowerShell из унаследованного окружения. SHA-256 переведён на потоковый .NET API. Проверки отказов усилены: они требуют нужную причину, а тест отката подтверждает достижение замены после удаления старого пакета.
- **CLI Preview:** русская справка в перенаправленном выводе CP1252 вызывала `UnicodeEncodeError`. CLI настраивает UTF-8 для stdout/stderr; регрессии проверяют справку, ошибки и имя файла с кириллицей и японскими символами.
- **Windows Python 2.7 и кириллица в пути:** файловые байты декодировались как UTF-8 перед `MoveFileExW`, что могло изменить имя. Теперь используется кодировка файловой системы со строгим декодированием. Добавлены воспроизведение CP1251 и реальный Windows-сценарий повторных сохранений, `.bak` и открытия профиля.
- **Покрытие recovery:** набор `test_recovery_limits.py` добавлен к заданию настоящего CPython 2.7.
- **Документация:** восстановлен фактический статус функций, явно перечислены оставшиеся пункты старого плана, добавлены актуальные снимки и исправлена ссылка на установку.

## Незавершённые пункты первоначального плана

| Пункт | Фактическое состояние |
|---|---|
| Стабильные идентификаторы техники | Прежний внутренний ключ `typeDescriptor.name` используется, но отдельная нормализованная идентичность и миграция запасных/старых строк не реализованы |
| Базовый и бонусный опыт | Есть `xp_base` и полученный `xp`; самостоятельного показателя бонусного опыта нет, новые источники ещё не сверены в игре |
| Полная экономика | Начисленные кредиты поддержаны; чистые кредиты доступны в нормализованном импорте, игровой адаптер оставляет их неизвестными |
| Новые метрики | Карта может отображаться ключом `arena:<ID>`; соответствие исходных полей итогам клиента остаётся неподтверждённым |
| Живые испытания | Новый пакет не имеет полного протокола |
| Стабильный выпуск | Нет испытанного stable-пакета, итогового SHA-256 и опубликованного стабильного тега |

Нумерация этапов 0.5–0.7 в одном кандидате не закрывает эти пункты. Они перечислены явно в [дорожной карте](roadmap.md).

## Игровые проверки, которые остаются открытыми

[Машинный протокол](release-validation.json) имеет `status: pending`, **13 из 13 обязательных сценариев не подтверждены**, хеш пакета, версия испытанного клиента и дата отсутствуют.

1. Победа, поражение и нулевой урон относительно официального результата; доступная ничья также остаётся сценарием первоначального плана.
2. Свежий отложенный результат и отсутствие повторного учёта.
3. Сохранность истории после перезапуска.
4. Изоляция аккаунтов и исключение реплеев.
5. Жизненный цикл Gameface при закрытии, входе в бой, отключении и возвращении.
6. Совпадение дополнительных метрик с официальными итогами.
7. Ввод и повторное сохранение настроек и целей, повторное открытие, CSV.
8. Установка, обновление, откат и удаление с сохранением данных.
9. Производительность на реальном журнале и клиенте.

Старые записи [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md) сохраняются как доказательства для старых пакетов. Автотесты не меняют их на подтверждение новой версии.

## Условия завершения

Нужно завершить перечисленные пункты исходного функционального плана, получить полный успешный CI итогового коммита, подготовить окончательные байты пакета и испытать именно их в целевом клиенте. Затем записываются фактические результаты, дата, версия и SHA-256; только после этого проходит gate стабильной публикации.

Смена `1.0.0-rc1` на `1.0.0` в метаданных меняет `.mtmod`. Хеш кандидата не разрешает автоматически опубликовать другой stable-пакет. Порядок описан в [RELEASE_RU.md](RELEASE_RU.md).
