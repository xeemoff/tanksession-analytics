# Проверка TankSession Analytics 2.0.0-rc2 в «Мире танков»

**RC2 требует повторной проверки исправлений.** В [протоколе совместимости](CLIENT_VALIDATION_RU.md) уже зафиксированы частичное испытание RC1 и SHA-256 установленного пакета. Ни успешный CI, ни отображение браузерного демо не подтверждают работу исправлений в Gameface.

## Сначала — найденные ошибки RC1

Работай по два действия за подход, фиксируя результат перед следующим этапом.

1. При закрытой игре распакуй весь Windows-архив RC2, запусти `manager.cmd` и обнови мод в выбранной версии клиента. Проверь SHA-256 установленного `.mtmod` против файла выпуска; каталог истории сохраняется.
2. Открой F8 → «Настройки», выбери высокий контраст и сохрани. Ожидаются подтверждение операции и доступная история; после закрытия и повторного открытия выбранный контраст должен остаться.

Затем проверь прокрутку в обе стороны и доступ к нижним настройкам, пять строк истории без перекрытия кнопками, горизонтальный счётчик страницы и читаемые подписи. Отдельные кнопки прокрутки в нижней части окна служат запасным управлением. После этого перезапусти клиент, проверь сохранённый вид и создай/измени тестовую цель.

Дополнительный опыт проверяется на **новом бое после установки RC2**: зафиксируй опыт до бонуса, примени бонус в официальных итогах, открой тот же бой в моде. Число боёв не должно расти, полученный и бонусный опыт должны обновиться. Старый бонус, применённый ещё в RC1, нельзя достоверно вычислить по общему итогу сессии; он не является новым испытанием обработчика.

История, время её получения и UTC-интервалы аналитики сохраняют прежний смысл. Два старых ожидания с ответом `not_available` не следует удалять ради чистого индикатора: свежий поздний результат проверяется отдельно.

## 1. Подготовить проверяемую сборку

Скачай готовый [Windows-архив RC2 со страницы выпуска](https://github.com/xeemoff/tanksession-analytics/releases/tag/v2.0.0-rc2). Для промежуточного кандидата открой успешный запуск **Tests and candidate builds** нужного коммита и проверь завершение всех заданий. Версия и хеш должны относиться к устанавливаемому файлу.

Для пакета:

```powershell
Get-FileHash .\ru.tanksession.analytics_2.0.0-rc2.mtmod -Algorithm SHA256
Get-Content .\ru.tanksession.analytics_2.0.0-rc2.mtmod.sha256
```

Сравни значения и запиши коммит, SHA-256, версию клиента и загрузчика в протокол. Наличие этого документа не означает, что любой найденный архив уже прошёл проверки.

Локальная сборка требует Python 3.9+, Node.js 20+ и отдельного CPython 2.7:

```powershell
cd ui
npm ci
npm run build
cd ..
python tools/build.py --python2 "C:\Python27\python.exe"
python tools/build.py --verify "dist\ru.tanksession.analytics_2.0.0-rc2.mtmod"
```

`--verify` проверяет состав, метаданные, CRC и заголовки, а не API и поведение игры.

## 2. Проверить браузерный интерфейс

Готовый preview запускается через `demo_hangar.cmd`. Из исходников после сборки UI:

```powershell
python tools/preview_ui.py --demo
```

На вымышленных данных проверь все разделы, историю за пределами первых 12 боёв, сессии, цели, контраст, плотность и пробный экспорт. Демо-профили и CSV временные и не изменяют реальные данные.

Собственная история в `preview_ui.py --data ... --account ...` по умолчанию доступна только для чтения. Запись настроек, целей и CSV разрешает `--allow-write`. Для такого испытания используй копию каталога данных при закрытой игре. Полные команды и смысл режимов — [GAMEFACE_RU.md](GAMEFACE_RU.md).

## 3. Обновить мод с сохранением данных

1. Закрой игру и локальные панели. Сделай копию всего каталога `mods/configs/tanksession_analytics/`.
2. Замени только пакет TankSession в `mods/<точная_версия_клиента>/`, оставив одну его версию. Сохрани `battles.jsonl`, pending-журнал, `settings.json`, `goals.json`, `profiles/` и `exports/`.

Проверь действующие [официальные правила модификаций](https://lesta.ru/support/ru/products/mt/article/15152/) и условия публикации. Не переноси сведения о совместимости старого кандидата на новую версию игры.

Основной сбор проверяй с выключенным экспериментальным кэшем. Для отдельного испытания окна установи внешний загрузчик и включи UI по [инструкции Gameface](GAMEFACE_RU.md). Зафиксируй возможный перезапуск при регистрации ресурсов.

## 4. Проверить обычное сохранение

| Сценарий | Что должно наблюдаться |
|---|---|
| Запуск | `[TankSession] Started; local data path:`; нет ошибки инициализации |
| Завершённый собственный бой | `Saved battle: complete` или объяснимый неполный результат |
| Победа, поражение, доступная ничья | Правильный исход относительно официального экрана |
| Нулевой урон | Известный ноль, а не пропуск |
| Более полный повтор | `Updated battle: complete`, один логический бой |
| Повтор того же результата | Число логических боёв не растёт |
| Перезапуск | Сохранённая история и дополнения остаются |
| Реплей | Новые реальные бои не записываются |
| Смена аккаунта | Данные и цели предыдущего аккаунта не показываются |

Сверь технику, исход, урон и полученный опыт с итоговым экраном. Физические строки JSONL могут содержать несколько ревизий одного боя; число строк не равно числу боёв.

## 5. Сверить новые показатели

Для 2.0.0-rc2 отдельно нужны реальные наблюдения следующих полей:

- тип машины, его стабильный ключ и соответствующая отображаемая подпись;
- уничтоженная техника, выстрелы, прямые попадания и пробития;
- состояние «выжил/погиб», включая нулевой код причины гибели;
- ID типа арены и локализованное имя карты из каталога;
- класс, уровень и нация конкретной техники, в том числе поздний результат после смены машины;
- начисленные/чистые кредиты и отдельные базовый/бонусный опыт;
- сохранение неизвестных значений для старых записей.

`xp_base` считается как `originalXP - achievementXP`; `xp_bonus` — как полученный `personal.xp` сверх базы. Все компоненты должны быть известны, разности неотрицательны. Сверь базовую строку с официальными итогами, затем проверь полученный опыт и вычисленную разницу. Не считай разницу суммой отдельных бустеров.

Чистые кредиты требуют режима с кодом 1/22/24, одной машины, подтверждённого avatar и всех компонентов начислений, удержаний, наград и фактических расходов. Сверь их с подробными итогами, включая округление и известный отрицательный доход. Золото, боны, складские предметы и будущая копилка в этот показатель не входят. Для неподдержанного или неполного результата ожидается неизвестное значение, а не ноль. [Полная формула](DATA_AND_UI_RU.md) сопоставлена со справочной **1.46.0.0_CT**, не с установленным клиентом; `complete` не обещает наличие всех дополнительных полей.

На копии прежней истории проверь переход от внутреннего имени/старой подписи к подтверждённому типу, отсутствие перезаписи старых JSONL-строк при чтении и сохранение числа логических боёв. Разные типы с одинаковой подписью должны остаться отдельными. Неоднозначная старая группа сохраняется в истории и не подтверждает одну машину для сравнения. Повторный результат того же боя может дописать идентичность ревизией, сохранив прежние показатели.

Для средних и долей проверь число известных значений. Пропуск не должен понижать среднее как фиктивный ноль. Точность и пробития должны использовать только записи с обоими известными совместимыми счётчиками.

Полная схема и ограничения — [DATA_AND_UI_RU.md](DATA_AND_UI_RU.md).

## 6. Проверить окно, профили и команды

| Проверка | Ожидаемое поведение |
|---|---|
| F8, Esc, крестик, повторное открытие | Одно окно; управление игрой возвращается после закрытия |
| Все вкладки, кириллица, размер, контраст | Доступное управление без обязательного колеса мыши |
| Аналитика и отчёты | Верные группы, календарь/часы UTC, периоды, покрытие; отсутствие метаданных видно |
| Темы, блоки, уменьшенное движение | Настройки сохраняются только для своего аккаунта; элементы доступны в Gameface |
| Предложенная цель Coach | Показаны основание и выборка; сохранение выполняется только после принятия |
| Поиск и сортировка | Применяются ко всей истории перед пагинацией; очистка возвращает исходный выбор |
| История более 12 боёв | Все страницы по пять записей; крайние кнопки отключены |
| Выбор техники и окна 10/30/100 | Корректный пересчёт без смены аккаунта |
| Тип, подпись и прежние фильтры | Выбор и цель следуют стабильному ключу; точный старый alias разрешается только в своём аккаунте; неоднозначность не объединяет машины |
| Сохранение вида и фильтров | Настройки текущего аккаунта восстановлены после закрытия и перезапуска |
| Создание, изменение, удаление цели | Меняется только цель; бои остаются; недостаточная выборка явно показана |
| CSV | Одна команда создаёт один файл со всей выбранной историей, а не текущей страницей |
| Автообновление после команды | Новый CSV или повторное сохранение сами по себе не запускаются |
| Ошибка записи профиля/экспорта | Понятное сообщение; история и предыдущий профиль не потеряны |
| Переход в бой, отключение, новый аккаунт | Окно закрыто, старые callback и данные не используются |

Проверь CSV в текстовом редакторе и табличном приложении: UTF-8 с BOM, разделитель `;`, подпись и необязательный ключ типа техники, базовый/бонусный опыт, начисленные/чистые кредиты, пустые неизвестные значения, отсутствие ID аккаунта и ID боя. В игре файлы находятся в `mods/configs/tanksession_analytics/exports/`.

Дни и сессии строятся по времени первого получения. Разрыв минимум 60 минут начинает новую сессию. Сравнение требует одной машины, одного известного режима, минимум 10 записей в каждой из двух сессий и полного урона. Недостаточную выборку не нужно искусственно считать успешным сравнением.

## 7. Отдельно испытать поздний результат

Экспериментальный кэш включай только для этого сценария. Зафиксируй начало собственного боя, досрочный выход, поступление официального результата и последующую запись. Старое ожидание с ответом `not_available` не является успешным восстановлением.

Проверь ситуацию с другим активным запросом: сигнал готовности свежего результата должен сохраниться в очереди и обработаться после ответа либо тайм-аута. Повтор сигнала не должен создавать дубль. Выход в бой, отключение и смена аккаунта должны отменять отложенную работу.

Если результат клиентом не выдан, оставь сценарий неподтверждённым. Наличие pending-записи само по себе не доказывает восстановление.

## 8. Диагностика и завершение проверки

```powershell
python tools/diagnose_log.py --log "D:\your-folder\python.log" --json
python tools/maintain_data.py --data "D:\your-folder\battles.jsonl"
```

Первая команда выводит агрегированные события TankSession; вторая проверяет журнал без компактирования. Для обсуждения достаточно версии клиента, хеша пакета, сценария и обезличенных счётчиков. Полный лог, ID и реальную историю в публичный репозиторий не загружай.

Проверь время открытия окна на своём объёме истории, отсутствие лишних зависаний, отключение UI/кэша и запуск после удаления пакета. При удалении убирай только `ru.tanksession.analytics_2.0.0-rc2.mtmod`; каталог данных сохраняй.

Запиши каждый реально пройденный сценарий в [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md), оставив остальные непроверенными. Стабильный игровой выпуск требует конкретного подтверждения совместимости и условий распространения; номер версии и успешные тесты его не заменяют.

## 9. Менеджер 2.0

На тестовой копии установки проверь поиск папки и её ручной выбор, установку с копиями данных, удаление и возврат пакета. Отдельно экспортируй историю и восстанови снимок в тестовую папку: исходная история должна остаться в проверенной копии. Не используй импорт как слияние журналов. Проверка выпусков выполняется только по кнопке, отказ сети не препятствует офлайн-операциям.
