# Проверка TankSession Analytics 0.4.0-rc4 в «Мире танков»

**Проверка реальной игры ещё не выполнена.** Этот документ — план испытаний. Успешный CI подтверждает только перечисленные автоматические проверки для конкретного коммита. Результат установки и игровые API нужно отдельно записать в [протокол совместимости](CLIENT_VALIDATION_RU.md).

## 1. Проверить панель и исходники

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
python tools/simulate_capture.py
python tools/launch_dashboard.py --demo
```

На странице используются 48 вымышленных боёв. Цели примера относятся к аккаунту `demo`. Проверь фильтры и CSV; закрой сервер через `Ctrl+C`.

## 2. Выбрать именно проверенный пакет

На GitHub открой **Actions → Tests and candidate builds → запуск нужного коммита**. Убедись, что завершены успешно Python 3 jobs, **React / TypeScript / browser preview** и **CPython 2.7 / reproducible mtmod**. После этого скачай artifact `tanksession-mtmod-candidate-...`.

В архиве находятся `.mtmod` и соответствующий `.sha256`. В PowerShell вычисли хеш пакета и сравни его с текстом контрольной суммы:

```powershell
Get-FileHash .\ru.tanksession.analytics_0.4.0-rc4.mtmod -Algorithm SHA256
Get-Content .\ru.tanksession.analytics_0.4.0-rc4.mtmod.sha256
```

Запиши SHA-256 и коммит в протокол. Это кандидат для испытания, а не подтверждённый игровой релиз. Артефакты Actions хранятся 14 дней.

Локальная альтернатива требует Python 3.9+ для инструмента, Node.js 20+ для сборки интерфейса и отдельного CPython 2.7 для компиляции:

```powershell
cd ui
npm ci
npm run build
cd ..
python tools/build.py --python2 "C:\Python27\python.exe"
python tools/build.py --verify "dist\ru.tanksession.analytics_0.4.0-rc4.mtmod"
```

Сборка проверяет собственный скомпилированный код. `--verify` проверяет состав, метаданные, CRC и заголовки; он не исполняет архив и не подтверждает API или поведение игры. Версию встроенного интерпретатора своего клиента также нужно подтвердить.

## 3. Установить пробный пакет

Сначала изучи [действующие правила модификаций](https://lesta.ru/support/ru/products/mt/article/15152/). Запиши точную версию клиента. При закрытой игре скопируй только свой пакет в соответствующий каталог `mods/<версия_клиента>/`, сохранив остальные файлы модификаций. Не устанавливай пакет для другой версии на основании одного успешного CI.

Экспериментальное восстановление из `battleResultsCache` оставь выключенным. Его API и callback проверяются отдельно.

Окно Gameface также выключено по умолчанию. Для отдельного испытания установи внешний загрузчик OpenWG Gameface для «Мира танков», включи `experimental_gameface_ui` и выполни [инструкцию окна](GAMEFACE_RU.md). Загрузчик может однократно перезапустить клиент при регистрации ресурса; его версию и это поведение укажи в протоколе.

## 4. Проверить обычный бой и последующие события

1. Запусти клиент. Найди `[TankSession] Started; local data path:` в `python.log`. Это подтверждает инициализацию адаптера, но ещё не получение результата.
2. Проведи свой обычный бой и дождись официального итогового экрана.
3. Найди `Saved battle: complete` либо `Saved battle: incomplete`. Для неполной записи более позднее событие может дать `Updated battle: complete`.
4. Сверь **танк, исход, урон, опыт и принадлежность аккаунту** с итоговым экраном. Неизвестное поле не должно выглядеть как ноль.
5. Открой панель через помощник или точный путь из лога. Проверь итог и CSV.
6. Повтори получение результата, перезапуск и досрочный выход в отдельных испытаниях. Две физические строки JSONL могут быть исходной записью и дополнением; в панели должен остаться **один логический бой**.
7. Если клиент не предоставил поздний результат, зафиксируй ограничение. Не считай наличие pending-записи доказательством автоматического восстановления.
8. При возможности проверь смену аккаунта и реплей. История и цели разных аккаунтов должны оставаться раздельными; реплей не должен добавлять бои.

Заполняй результаты в [таблице сценариев](CLIENT_VALIDATION_RU.md). Для первого подтверждения достаточно описать фактически пройденные случаи; непроверенные оставь отмеченными как непроверенные.

Для нового окна отдельно проверь F8/Esc, фильтры, отсутствие второй копии окна, обновление после результата, закрытие при выходе в бой или смене аккаунта, доступность управления после закрытия. Сопоставь показатели со своей историей и послебоевым экраном. Снимок браузерного демо не подтверждает эти сценарии.

## 5. Диагностика

```powershell
python tools/diagnose_log.py --log "D:\your-folder\python.log" --json
python tools/maintain_data.py --data "D:\your-folder\battles.jsonl"
```

Первая команда выводит только счётчики событий TankSession, без исходных строк, путей и ID. Вторая считает корректные бои, ревизии, дубли, некорректные строки и конфликты в файле.

- `identity_missing` / `account_mismatch`: результат нельзя уверенно связать с аккаунтом.
- `replay_api_unavailable`: проверка режима реплея недоступна, сбор приостановлен.
- `startup_error`: не удалось пройти одну из стадий запуска.
- `battle_updated`: запись дополнена; это не новый бой.
- `battle_conflict`: новые данные противоречат известным, старая запись сохранена.

Для обсуждения неисправности нужны версия клиента, сценарий и счётчики. Полный `python.log` и реальный журнал в публичный репозиторий не загружай.

## 6. Удаление и условия релиза

При закрытой игре удали только установленный `ru.tanksession.analytics_0.4.0-rc4.mtmod`. Проверь запуск без него. История удаляется отдельно по желанию пользователя.

К проверенному игровому релизу можно переходить после подтверждения загрузки, игровых полей, отсутствия дублей и смешения аккаунтов, испытания удаления и проверки действующих правил. Добавь настоящие скриншоты/видео и заполненный протокол. Сборка, демоданные и имитационные тесты сами по себе этого не заменяют.
