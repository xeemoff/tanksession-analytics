# Проверка TankSession Analytics v0.4.0-rc2 в «Мире танков»

**Важно:** этот документ — тест-план. Ни компиляция Python 2.7, ни установка, ни API актуального игрового клиента на стороне автора проекта пока не проверены. Не распространяйте пакет как готовый мод до проверки в установленной версии игры.

## 1. Проверить исходники без игры

В PowerShell, из корня репозитория:

```powershell
py -3 -m unittest discover -s tests -v
py -3 tools/simulate_capture.py
py -3 tools/dashboard.py
```

Откройте `http://127.0.0.1:8765/`. По умолчанию используются **48 синтетических боёв**. Закройте сервер через `Ctrl+C`.

## 2. Создать пробный `.mtmod`

Нужен Python 3.9+ для `tools/build.py` и **отдельный, настоящий Python 2.7** для компиляции игровых скриптов. Не скачивайте случайные исполняемые файлы из непроверенных источников. Python 2.7 давно не поддерживается: применяйте его только в изолированном окружении сборки.

```powershell
py -3 tools/build.py --python2 "C:\Python27\python.exe"
py -3 tools/build.py --verify "dist\ru.tanksession.analytics_0.4.0-rc2.mtmod"
```

Проверка архива подтверждает только **структуру**, наличие байткода и формат ZIP, а **не** то, что мод действительно работает с текущей игрой.

Проверьте правила модификаций: https://lesta.ru/support/ru/products/mt/article/15152/ . Игра должна быть закрыта до копирования файлов. Сделайте резервную копию файлов модификаций, затем поместите **только** созданный `.mtmod` в `mods/<версия_игры>/` своего клиента; не заменяйте чужие файлы. Установку проводите на свой страх и риск в тестовом окружении.

## 3. Проверить загрузку и один бой

1. Запустите клиент и откройте его `python.log`.
2. Убедитесь, что появляется `[TankSession] Started; local data path: ...`.
3. Проведите обычный бой, дождитесь официального окна результатов.
4. Проверьте сообщение `[TankSession] Saved battle:`; число или идентификатор **не нужно никуда отправлять**.
5. Найдите `battles.jsonl` по пути из логов. Сверьте танк, исход, урон и опыт с экраном результатов.
6. Повторите минимум три раза, включая досрочный выход из боя и перезапуск игры. После повторного callback должна сохраняться одна запись на бой.
7. Если появляется `identity_missing`, `account_mismatch` или `Skipped incomplete/ambiguous`, ничего не обходите принудительно: запишите только **счётчики** для диагностики.
8. Не включайте `experimental_cache_recovery`, пока не подтверждён API кэша вашей версии клиента.

## 4. Безопасная диагностика

Скопируйте `python.log` в доступную папку и выполните:

```powershell
py -3 tools/diagnose_log.py --log "C:\путь\к\python.log"
```

Команда печатает **только агрегированные счётчики** событий TankSession; она не показывает названия личных файлов, ID аккаунтов, арены и исходные строки. Можно отправить мне получившиеся счётчики и кратко описать, какой шаг не сработал. **Не отправляйте оригинальные логи, содержимое `battles.jsonl` и реальные ID**.

При необходимости для сохранения отчёта:

```powershell
py -3 tools/diagnose_log.py --log "C:\путь\к\python.log" --json > diagnostics.json
```

## 5. Если игра не загружается

Полностью выйдите из игры и удалите только установленный `ru.tanksession.analytics_0.4.0-rc2.mtmod`. После этого проверьте запуск без мода. Подробный список известных ограничений — [integration.md](integration.md). Не включайте экспериментальные функции для обхода ошибки.

## 6. Критерии перехода от RC к релизу

- Сборка с реальным Python 2.7 создаёт пакет, который загружает установленный клиент.
- Загрузчик, игровые события и поля результата проверены **на реальных результатах своего аккаунта**.
- Нет дублей и смешения данных между аккаунтами.
- Выход до окончания боя и повторный вход корректно проверены.
- Ни одна функция не предоставляет запрещённого преимущества в бою.
- Тесты CI проходят и README содержит скриншот реальной работы (без чужих данных).
