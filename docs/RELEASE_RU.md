# Подготовка и публикация выпуска

## Каналы поставки

- Версия вида `2.0.0-rc3` — предварительный выпуск для испытаний. Windows-архив содержит проверенный по структуре `.mtmod`, хеши, автономный установщик, инструкцию и примечания.
- Версия вида `2.0.0` — стабильный выпуск. Для её упаковки и публикации нужны результаты живой проверки **того же `.mtmod`**, указанного клиента и всех обязательных сценариев.

Выпуск 2.0 включает также проверенный Preview и самостоятельные Native Windows/Linux архивы. Это разные программы с разными требованиями: игровой Windows ZIP не требует Python/Node; Preview и адаптер Native требуют Python 3.9+. C++-бинарник не устанавливается в игру. Имена, SHA-256, версия и исходный коммит Native проверяются перед публикацией; в поставку попадают артефакты того же полного CI.

Манифест [release-validation.json](release-validation.json) хранит статус проверки. Сейчас `pending` означает, что новая версия не прошла весь протокол. Автотесты не устанавливают `verified` и не меняют результаты оператора.

## Воспроизводимая упаковка

Сначала собери UI и `.mtmod` штатными инструментами, затем:

```text
python tools/package_release.py
```

Для проверки тега:

```text
python tools/package_release.py --tag v2.0.0-rc3
```

Тег обязан точно совпадать с `v` + версией `src/meta.xml`. Инструмент проверяет пакет, его SHA-256 и обязательные файлы, читает примечания из `docs/releases/v<версия>.md`. Он не собирает содержимое всей рабочей папки: в ZIP попадает только явный список файлов. Реальная история, настройки, логи, чужие моды и внешние загрузчики в этот список не входят.

Даты, порядок, права и метод сжатия ZIP фиксированы. При одинаковых входных файлах и среде упаковки результат совпадает побайтно. Хеш Windows-архива и `.mtmod` различается: это контрольные суммы двух разных файлов.

## Формат обновления Windows-менеджера

Начиная с RC3 `manifest.json` содержит `manager_update_protocol: 1`; архив включает `Start-TankSession.ps1` и `Update-TankSession.ps1`. Плоский разрешённый состав должен совпадать с `Get-TankSessionBundleNames`, упаковкой и Windows-регрессиями. Любое расширение состава требует совместимого перехода bootstrap, поскольку прежний доверенный менеджер проверяет новые файлы до их исполнения.

После публикации сверяются все десять assets: пять файлов и пять SHA-256. Для Windows ZIP дополнительно сверяются вложенный `.mtmod` с отдельным asset, манифест и точные исходники установщика из коммита выпуска. Native-архивы должны указывать тот же `source_commit`; Preview должен содержать те же собранные ресурсы интерфейса. CRLF исходных текстов в Windows Native-кандидате учитывается отдельно от проверки сырых хешей его членов.

## Переход со сборки-кандидата к стабильной версии

1. Внеси окончательные изменения и согласуй предполагаемую стабильную версию в `src/meta.xml`, Python `__version__` и метаданных UI; подготовь соответствующие release notes. Обычный CI создаёт `.mtmod` для проверки даже до разрешения стабильной публикации. Изменение запроса публикации или stable-тег выполняется только после остальных шагов.
2. Испытай именно этот `.mtmod` в целевом клиенте. Зафиксируй версию клиента, хеш, дату и результаты в [CLIENT_VALIDATION_RU.md](CLIENT_VALIDATION_RU.md). Не дописывай результаты сценариев, которые фактически не проверялись.
3. Обнови `release-validation.json`: `status: verified`, `release_version`, `tested_client_version`, `tested_package_sha256`, `tested_at` в формате `YYYY-MM-DD` и все перечисленные сценарии. Укажи относительный путь к протоколу в `evidence`.
4. Повтори CI и проверь хеш готового пакета. Изменение Python, JS, CSS, метаданных или включённых ресурсов после игрового теста требует новой сборки и повторной проверки. Исправление документации не должно менять `.mtmod`.
5. Создай новый тег `v<версия>` на проверенном коммите или явно обнови `.github/release-request.json` с этим тегом и перенеси изменение в `main`. Во втором случае workflow создаёт тег на проверенном коммите основной ветки. Обычная правка кода или документации без изменения файла запроса выпуск не запускает. Workflow повторяет автоматические проверки и упаковку; несовпадение хеша, версии или незакрытый протокол останавливают стабильный выпуск.

Тег уже опубликованного выпуска не перемещают. Исправления выпускают под новой версией. Прежние версии не удаляются автоматически.

## Что проверяет автоматический gate

Обязательные сценарии: победа, поражение, нулевой урон, свежий отложенный результат, отсутствие дублей, сохранение истории при перезапуске, разделение аккаунтов, исключение реплеев, жизненный цикл Gameface, совпадение метрик с отчётом, настройки/цели/экспорт, установка/удаление, производительность. Для каждого нужен фактический результат. Неизвестное значение в журнале не считается нулём и не подтверждает поддержку метрики.

Для стабильного канала также проверяются точная версия, версия целевого клиента, 64-значный SHA-256 именно проверенного пакета, корректная дата и наличие протокола. Это защита от случайного выпуска непроверенной сборки; сам JSON не служит независимым доказательством испытаний.

## Правила распространения

Назначение TankSession — собственная статистика после боя и окно в ангаре. В [официальном перечне запрещённых модификаций](https://lesta.ru/support/ru/products/mt/article/15152/) отдельно обсуждаются дополнительные сведения в бою; это не является индивидуальным одобрением конкретного мода.

Для публикации на форуме действуют [правила размещения модификаций](https://forum.tanki.su/topic/2200656-правила-публикации-модификаций/): своя тема, версия клиента в начале названия, описание, прямая загрузка, инструкция, сведения об ограничениях и до трёх содержательных скриншотов для интерфейсного мода. Тема проходит модерацию и должна поддерживаться после обновлений клиента. Перед публикацией повторно проверь эти правила и [лицензионное соглашение](https://legal.lesta.ru/eula/).

Проверка источников: 26.11.2026. Скриншоты браузерного демо с синтетическими боями подписываются как демо; они не подтверждают работу в игре. Чужие ресурсы клиента и загрузчик OpenWG не входят в выпуск. Инструкция и хеши доступны рядом со скачиванием.
